## Human playthrough checklist

A normal, curiosity-led playthrough is more useful than trying to behave like a software tester. Where practical, cover the following during the same overall playthrough:

1. **Title / home screen**
   - Does the first impression feel polished and inviting?
   - Are Continue, New Game, My Unicorn and Settings obvious enough for the situation?
   - Does anything look busy, cheap, confusing or unfinished?

2. **New Game and unicorn creator**
   - Start a New Game.
   - Create and name a unicorn.
   - Try several body, hair, mane, tail, horn, marking and accessory choices.
   - Try Surprise Me if it feels natural.
   - Note whether creating the unicorn feels fun or like admin.

3. **Returning-player routes**
   - Return to the title screen when convenient.
   - Use Continue.
   - Open My Unicorn / Redesign and make a change.
   - Confirm the saved unicorn still feels like the same character afterwards.

4. **Settings and accessibility**
   - Open Settings from the title and, where practical, from play.
   - Try audio controls.
   - Try Reduced Motion and High Visibility briefly.
   - Note anything whose label or effect is unclear.

5. **Controls and navigation**
   - Use the controls you would normally use.
   - If convenient, try both keyboard and touch/mobile controls.
   - Look for accidental key capture, awkward interaction targets, getting stuck, or unclear exits/back actions.

6. **Core game loop**
   - Play the existing story/exploration flow naturally.
   - Visit home/cottage activities where they arise.
   - Try racing/activity content where practical.
   - Talk to characters and use dialogue choices where available.
   - Notice whether objectives and next steps remain understandable without outside explanation.

7. **Presentation and delight**
   - Notice dialogue portraits, transitions, ambience, effects and audio.
   - Call out anything visually inconsistent or distracting.
   - Equally important: note anything that gets revisited voluntarily because it is enjoyable.

## Feedback to capture

Free-form notes are fine. The most useful feedback normally falls into these buckets:

- **Broken:** crashes, freezes, impossible progression, controls failing, save/Continue problems.
- **Confusing:** unclear objective, unclear button, uncertainty about what to do next.
- **Boring/frustrating:** a section dragged, repeated too much, felt fiddly or was skipped deliberately.
- **Delight:** anything funny, pretty, satisfying or repeatedly revisited.
- **Requests:** spontaneous wishes for a character, place, activity, cosmetic, story beat or feature.
- **Polish:** visual/audio/layout issues that automation did not expose.

Screenshots are useful for visual issues, but plain descriptions are enough for gameplay or feel problems.
