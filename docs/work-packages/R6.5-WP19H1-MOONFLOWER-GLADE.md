# R6.5-WP19H1 - Moonflower Glade Final Polish

Approved scope recorded from David's Moonflower Glade review on 14 September 2026 and refined through a second architecture/design pass before implementation.

H1 is the first package in the open-ended H1+ area-by-area final polish programme. Moonflower Glade is the review lens, not the technical boundary. Local Glade work belongs here, while defects exposed by the Glade that are actually shared across exploration scenes must be fixed at their canonical shared owner and regression-tested wherever relevant.

## Current stage

**Completed and human-approved on 15 September 2026.** H1.1-H1.10 were delivered through iterative visual/gameplay review, H1.11 then consolidated the implementation and removed legacy suppression/workaround debt without changing the approved Glade result. The final qualified runtime head before documentation-only completion commits was `8dff0c5f9bd1c49212b5cb9d14d177d32483587f`; it passed formatting, lint, architecture, verification/performance policy, type-check, unit contracts, production build, static smoke, performance architecture, all three full Chromium shards and the Firefox/WebKit/Chromium compatibility matrix. David explicitly authorised final documentation, merge and deployment.

The package is closed. Future work should use the conventions captured in `docs/engineering/H1-WORLD-IMPLEMENTATION-CONVENTIONS.md`; the next area review, if/when started, becomes R6.5-WP19H2 rather than extending H1. Documentation-only completion commits are separately verified before merge.

## Product intent

Moonflower Glade should become a convincing home region rather than a functional starting map. It should feel cosy, natural, lived-in, slightly magical and deliberately expandable. The player should immediately understand that the cottage is home, the Glade belongs to a larger world, environmental boundaries are physical, and points of interest are communicated through world design rather than development-style floating icons.

Preserve existing positive gameplay, progression, save compatibility, input methods, audio behaviour and accepted R6.5 UI unless this package explicitly owns a correction.

## Second-pass decisions

The second pass narrows and clarifies the initial review in five important ways:

- **H1 is not a disguised whole-game overhaul.** Shared-system work is included only where Moonflower exposes a genuine reusable defect: click/tap approach behaviour, dialogue presentation, interaction affordances, NPC art clipping where the shared pipeline is responsible, collision/depth conventions and gateway presentation.
- **Future features get foundations, not full implementations.** Farming/growing, fishing, the western-gate unlock quest, the region beyond that gate, seasonal home evolution and broader Pip companion appearances are deferred. H1 may add data/model/render hooks required to avoid rebuilding the area later.
- **The cottage exterior extends the existing home architecture.** Do not create a second unrelated customisation system. H1 should make the default exterior data-driven/configurable enough for later roof/wall/door/window/garden variants, while keeping the current player experience simple.
- **Interaction markers and click navigation remain separate concepts.** A small blue magical pinprick identifies a persistent interactable. The existing temporary click/tap destination marker remains a different visual language. Pip's mysterious trail remains story-specific and must not look like either.
- **World art must explain world collision.** Dense trees, hedges, cottage mass and water can form boundaries, but invisible walls should not compensate for scenery that visually says the player can pass.

## H1A - Spatial composition, path and future western expansion

Recompose the western half of Moonflower Glade:

- reroute the main path so it passes Moonflower Cottage rather than visually terminating at its door;
- create a smaller cottage path branching from the main route;
- continue the main route west/left towards a substantial hedge boundary;
- build a visible gate into that hedge as a future world expansion point;
- make the gate initially locked and capable of producing a simple locked response;
- represent the gate as a proper world/gateway state so a later quest can unlock it without rebuilding the map;
- do not create the later key quest or destination region in H1.

The revised composition must preserve readable traversal to the bridge, Moonflower Field and Sunbeam Village.

## H1B - Moonflower Cottage exterior and front garden

Significantly redesign the cottage exterior so it reads as a warm home rather than an abstract face/witch-hat silhouette.

Required direction:

- more convincing wall and roof texture;
- stronger door/window/trim detail;
- warm domestic details such as pots, baskets, window boxes, climbing plants or equivalent restrained decoration;
- retain whimsical fantasy character without making the building visually grotesque or over-stylised;
- create coherent flower beds to both sides of the frontage;
- increase flower variety and ensure foreground flowers render in front of the cottage where appropriate;
- use the revised branch path to create an actual front-garden composition rather than placing the building directly on the main road.

### Exterior-customisation foundation

H1 must establish a clean exterior-home presentation model rather than hard-coding the redesigned cottage as another permanent monolith.

The model should be compatible with the existing home-decoration/save architecture and leave clean future categories for items such as:

- roof treatment;
- wall treatment;
- door;
- window/trim treatment;
- window boxes;
- exterior ornaments;
- front-garden decoration.

H1 does **not** need a full exterior decorating UI, shop catalogue or broad player-facing customisation loop. Existing saves must receive sensible defaults through normal migration/reconciliation rules if persisted exterior state is introduced.

## H1C - Garden plot and future growing loop

Keep the existing vegetable/garden plot as a deliberate future gameplay area.

H1 should:

- preserve enough usable space around it;
- improve its integration with the cottage garden where necessary;
- avoid burying it under scenery;
- optionally define inactive future planting positions/data if this can be done cleanly without implementing farming.

Seed planting, timed growth, harvesting, cooking/gifting integration and crop progression are deferred.

## H1D - Remove the outdoor Wonderbook and create the Home Meadow

The physical Wonderbook/display stump no longer belongs outside now that the Wonderbook is globally accessible from the exploration UI.

H1 should:

- remove the outdoor Wonderbook/display stump, its Glade interaction and its collider;
- place the physical Wonderbook inside Moonflower Cottage, preserving global menu access;
- convert the vacated area opposite the cottage into a calm home meadow/open garden rather than another mandatory activity zone.

The meadow may use mixed wildflowers, longer grass, butterflies/fireflies, stones, a log/bench or similarly restrained natural detail. It should provide visual breathing room and remain suitable for later ambient visits, picnics or seasonal changes without prebuilding those systems now.

## H1E - Environmental boundaries, tree collision and ground texture

Strengthen the Glade's environmental framing:

- add denser trees along the lower boundary on both sides of the stream;
- continue the boundary around the right side towards the Sunbeam Village entrance;
- add more northern tree cover around the Hollow Tree area;
- improve tree/trunk detail where useful;
- ensure every tree/hedge used as a hard visual boundary has a believable matching trunk/root/hedge collider;
- avoid canopy-sized colliders that block open-looking ground;
- remove or prevent locations where the player can visibly walk through a tree trunk;
- add restrained grass/ground variation, small plant clusters, stones/leaves and soft object shadows without creating obvious repeated tiling.

Treat the rule **visual hard boundary = physical hard boundary** as a shared exploration-world contract where appropriate.

## H1F - Stream life and future fishing hook

Keep the current stream layout unless the spatial rework requires minor alignment changes.

Polish it with:

- less regular highlight/ripple placement;
- subtle animated surface variation;
- lightweight fish that generally travel from the top of the stream towards the bottom with varied timing, horizontal position and speed;
- occasional surfacing/ripple behaviour if it remains visually clean;
- no collision or navigation interference.

Fish should be implemented as reusable ambient entities rather than permanently painted marks so a later fishing system can hook into the stream cleanly. Actual fishing mechanics, rods, catches and rewards are deferred.

## H1G - Pip production identity and Glade story clarity

Pip needs a deliberate production identity. The current primitive floating-pig-like presentation is no longer sufficient beside the rest of the game's art.

H1 should:

- define Pip explicitly as a magical companion creature/species rather than leaving the body/lore ambiguous;
- give Pip a clear head/body silhouette, readable small-scale shape and proper production art;
- preserve the floating/bobbing quality if it suits the final design;
- support facial/emotional readability;
- ensure Pip is clearly distinct from unicorns.

Pip may become a more recurring companion in later packages, but H1 only establishes the identity and ensures the Glade version is production quality.

### Pip's Mysterious Trail

Trace and repair the existing secret/discovery flow rather than adding a parallel system. The player must never be shown an obviously significant trail and then receive no meaningful response.

For each relevant progression state, approaching the trail must produce one of:

- a valid action;
- clear feedback;
- a clear indication that Pip or another next step is required.

Keep the trail visually distinct from normal interaction pinpricks and click/tap destination markers.

## H1H - Universal world-interaction affordance

Retire literal floating bridge/house/object icons used as persistent world interaction markers.

Introduce a reusable shared affordance: a small blue magical pinprick/glow that gently pulses at or near an interactable point.

Requirements:

- subtle enough not to dominate scenery;
- readable on the supported backgrounds;
- one canonical implementation owned by the shared interaction/presentation system;
- usable for normal interactable objects throughout the world;
- compatible with reduced-motion settings;
- visually distinct from click/tap movement destination feedback and story-specific effects.

Moonflower Glade is the first area to adopt the polished affordance, but the implementation must be reusable rather than scene-specific.

## H1I - Moonflower Field integration and flower-depth rework

Moonflower Field is now a continuous part of Moonflower Glade rather than a separate Moonflower Patch scene. This supersedes the original separate-scene requirement following David's H1.5 review.

Required changes:

- stop the branch path at the field edge rather than continuing through/down the flower area;
- keep the Moonflower Field sign off the walking path and integrate it into the field composition;
- fill the land to the right of the approach with a dense, mixed-colour flower field;
- vary flower size/spacing so the field does not read as repeated decals;
- use shared world depth/occlusion conventions so some flowers pass behind the unicorn and some occlude its lower body as it moves through them;
- retire the obsolete field-entry interaction, threshold glimmer and MoonflowerPatchScene;
- place Willow's three special glowing Moonflowers directly amongst the Glade field;
- allow those special Moonflowers to be collected at any time, including before the Willow quest starts;
- preserve collection through the existing Moonflower inventory item and quantity rules;
- make Willow's conversation inventory-aware so arriving with all three immediately satisfies the collection requirement, while players without them are directed to Moonflower Field and can return normally after collecting them.

The desired experience is **path -> field -> walk naturally through flowers -> collect special Moonflowers in-world -> continue exploring**, with no scene transition.

### Sunbeam Village gateway

Replace label-like destination presentation with a physical decorative gateway/arch whose sign is part of the world art. Use the shared region-gateway owner so later exits can receive the same treatment without duplication.

### Hollow Tree

Preserve the Hollow Tree concept and gameplay. Apply only bounded polish:

- improved surrounding vegetation where useful;
- stronger northern boundary composition;
- shared blue interaction affordance if an interaction marker is required;
- preserve correct existing collision and transition behaviour.

## H1K - Juniper tail clipping and NPC presentation audit

Fix Juniper's visibly cropped/clipped tail during movement.

The implementation must first determine whether the problem is caused by:

- source art bounds;
- animation/frame crop;
- origin/display sizing;
- parent container or mask;
- shared NPC presentation logic.

If the cause is shared, fix the canonical NPC art/presentation path and regression-check other affected moving residents. Do not apply an arbitrary Juniper-only positional offset unless the defect is genuinely unique to that asset.

## H1L - Global dialogue-card polish

Use the shared DialogueCard/UI design system so every ordinary world conversation benefits from the correction.

Required direction:

- rounded dialogue-panel corners consistent with the approved R6.5 design language;
- matching rounded shadows rather than square-corner shadows beneath rounded controls;
- rounded Continue/Done and choice buttons;
- improved padding, border weight and restrained surface treatment;
- move the Continue/Done action upwards so it sits comfortably inside the panel;
- keep compact and expanded dialogue layouts consistent;
- preserve readable text areas and touch targets;
- preserve reduced-motion/accessibility behaviour.

For the speaker portrait, deliberately lean into the overlap rather than leaving an accidental bulge: the portrait may overlap the left edge, but spacing, halo/shadow and text layout must make that clearly intentional.

## H1M - Global click/tap approach-to-interact repair

Moonflower review exposed a global defect: click/tap navigation targets raw world coordinates and can repeatedly drive the player into NPC collision until the stuck timeout cancels navigation. This presents as visible shuddering/bouncing.

H1 must connect click/tap navigation with the canonical interaction system.

### Required behaviour

Normal ground click/tap:

- navigate to a reachable location and stop normally.

Click/tap on or near an NPC/interactable:

- identify the interaction target;
- choose a reachable stand-off/approach position rather than the object's centre;
- navigate until the player is inside the target's valid interaction range;
- stop cleanly and face the target;
- expose the normal Talk/Interact/Enter action.

Do **not** require automatic conversation activation. The default H1 behaviour should be **click NPC -> approach -> stop in range -> show Talk**, preserving explicit player control.

For moving NPCs, approach targeting may be recalculated at a controlled interval if required, but must not chase the exact centre every frame.

Ordinary ground clicks inside known static collision should resolve to the nearest valid reachable point or fail cleanly. The existing stuck timeout remains a last-resort safety mechanism, not the expected destination-validation method.

### Regression matrix

Cover at minimum:

- click directly on a stationary NPC;
- click behind a stationary NPC;
- approach from multiple sides;
- moving NPC approach;
- Pip approach;
- click just outside interaction range;
- static scenery/blocked destination;
- keyboard interruption;
- touch-control interruption;
- dialogue beginning while navigation is active;
- scene transition while navigation is active.

Acceptance requirement: no repeated visible collision oscillation/shudder.

## H1N - Optional bounded atmosphere polish

Only after the required H1 scope is stable, add low-risk atmosphere improvements where they materially improve the Glade and do not delay acceptance:

- subtle stream ambience near the water;
- restrained birds/insects/rustling;
- lightweight foliage motion;
- butterflies or equivalent meadow life.

Use the existing audio/accessibility systems. These are optional polish, not blockers if the required package is already visually complete.

## Definition of done

H1 was accepted after the following were satisfied:

- Moonflower Glade reads as a finished home region rather than a prototype starting map;
- the main path passes the cottage and visually promises future western exploration;
- the locked hedge gate exists as a clean future expansion hook without implementing the later quest;
- the redesigned cottage is clearly homely and its exterior has a future-compatible configuration model;
- the front garden and retained growing plot feel intentional;
- the outdoor Wonderbook/display stump is gone and its former area is a deliberate Home Meadow;
- visual hard boundaries have matching believable collision and the player cannot walk through boundary tree trunks;
- the stream feels less static and includes lightweight ambient fish;
- Pip has a coherent production identity and the Mysterious Trail gives meaningful progression feedback;
- normal persistent interactables use the shared interaction language rather than literal floating object icons;
- Moonflower Field is dense, multicoloured, properly layered, continuous with the Glade and supports Willow's collectible Moonflowers without a separate scene;
- Sunbeam Village signage is integrated into physical world presentation;
- Hollow Tree retains its strengths with bounded texture/environment polish;
- Juniper's tail no longer clips and the shared NPC-art root cause is corrected;
- the shared dialogue card matches the approved rounded R6.5 UI language and no controls overlap its lower edge;
- click/tap navigation approaches NPCs/interactables without shuddering and stops within valid interaction range;
- existing progression, saves and accepted input behaviour remain intact;
- automated, responsive and cross-browser qualification is green;
- David explicitly accepted H1 and authorised merge/deployment.

H1 is complete. Any later area review starts as R6.5-WP19H2 rather than extending this package.
