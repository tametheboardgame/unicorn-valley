# R6.5-WP18J - Bag, Map & Wonderbook Themed Presentation Polish

Status: **implemented / automated validation pending / human visual gate required**

Date started: 2026-09-07

Implementation branch: `work/r6.5-wp18j-bag-map-book-polish`

Stacked base: `agent/r6.5-wp18i-concept-grade-ui` (WP18I PR #156)

## Objective

Apply one tightly bounded themed presentation pass to Bag, Map and Wonderbook so each surface reads immediately as the object it represents rather than as a generic modal panel.

WP18J is visual presentation only. It must preserve the existing inventory, map topology, discovery, collection, progression, save and input behaviour established before this package.

## Visual authority

The approved visual direction established during the 2026-09-07 UI review remains authoritative:

- Bag: a magical satchel/saddlebag, using restrained leather, pocket, stitch, tag and compartment cues.
- Map: a bright magical quest/adventure map, using parchment, cartographic terrain, compass and trail cues.
- Wonderbook: a friendly enchanted story/spellbook, using a coherent open-book spread, visible binding, chapter/ribbon hierarchy and subtle magical flourishes.

The implementation should stay child-friendly, readable at first glance and consistent with the concept-grade WP18I visual language.

## Hard scope

### Bag

- strengthen the overall satchel/saddlebag silhouette;
- make pocket tabs read as attached labelled compartments;
- strengthen object slots without changing item hit targets or semantics;
- make the selected object unmistakable;
- visually link the selected slot to a dedicated treasure-tag detail area;
- retain food-use, Shop, quantity, scroll, pocket and Shimmer behaviour.

### Map

- replace the plain-panel read with a parchment adventure-map surface;
- add restrained terrain/cartographic texture and compass treatment;
- improve trail and node contrast while preserving the topology exactly;
- keep the current-location emphasis and homeward/nearby guidance intact;
- retain the existing physical/dotted-path semantics.

### Wonderbook

- strengthen the outer cover, page stack, spine and two-page spread;
- make section controls read as chapter/ribbon tabs;
- improve hierarchy between page headings, entry cards, stickers and badges;
- retain all section, filter, page-turn, close and portrait-companion behaviour;
- preserve the existing progress/collection model exactly.

## Explicit exclusions

WP18J does not authorise:

- new inventory or item semantics;
- new map travel or fast travel;
- map topology changes;
- new regions, discoveries, quests, story, unlocks or collections;
- Wonderbook progression-rule changes;
- save-schema changes;
- input/control redesign;
- settings, creator, title/profile or world-HUD changes;
- collision or world-art remediation;
- reopening the broader WP18I shell.

## Implementation

### `src/game/scenes/InventoryScene.ts`

- replaced the generic modal shell with a more object-like framed presentation while retaining the same scene lifecycle and close path;
- added a stitched satchel body, leather-like compartment framing and pocket tags;
- strengthened selected-item presentation with a dedicated selected state, icon well and treasure-tag detail panel;
- retained existing named interactive objects and preserved their touch areas closely enough for the existing regression coordinates;
- replaced the flat map surface with parchment layers, restrained terrain washes, stitched/map-edge detail, compass treatment and warmer route/node styling;
- preserved `VALLEY_MAP_CONNECTIONS`, `VALLEY_MAP_NODES`, current-location selection and guidance logic unchanged.

### `src/game/scenes/WonderbookScene.ts`

- strengthened the open-book silhouette with cover, layered page edges, spine, ribbon markers and magical flourishes;
- increased chapter-tab hierarchy without changing tab names or pointer handlers;
- added paper-card framing and sticker depth to collection/progress entries;
- retained all section, discovery-filter, pagination, close and portrait-companion logic unchanged.

## Behaviour preserved by construction

- `FoodUseService` behaviour;

- `ValleyMapTopology` data or route calculation;

## Human visual acceptance gate

WP18J is not complete until the user visually checks the same three surfaces on the target landscape-tablet presentation:

1. Bag
2. Map
3. Wonderbook

Acceptance questions:

- Does Bag immediately read as a magical satchel rather than a generic inventory window?
- Is the selected item visually obvious and clearly linked to its description/actions?
- Does Map immediately read as a bright magical adventure map while remaining easy to read?
- Is `YOU ARE HERE` and the route/homeward context still obvious?
- Does Wonderbook convincingly read as an enchanted open book rather than two generic panels?
- Are tabs, page content, stickers, badges and page controls clearly hierarchical?
- Are alignment, spacing, border density and shadowing cleaner than the pre-WP18J screenshots?
- Is all touch interaction still comfortable and unchanged in intent?

## Completion rule

Do not merge or deploy WP18J solely on automated green status. Human screenshot/visual approval remains mandatory.

After approval and merge, R6.5-WP18H can resume the full human tablet replay and return to WP17 for the explicit R7-readiness decision.
