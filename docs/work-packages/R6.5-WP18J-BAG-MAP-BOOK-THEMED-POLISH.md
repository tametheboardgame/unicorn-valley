# R6.5-WP18J - Bag, Map & Wonderbook Themed Presentation Polish

Status: **remediation authorised / implementation in progress / human visual gate required**

Date started: 2026-09-07

Implementation branch: `work/r6.5-wp18j-bag-map-book-polish`

Stacked base: `agent/r6.5-wp18i-concept-grade-ui` (WP18I PR #156)

## Objective

Apply one tightly bounded themed presentation pass to Bag, Map and Wonderbook so each surface reads immediately as the object it represents rather than as a generic modal panel.

Following the first landscape-tablet visual review, WP18J also owns one bounded remediation pass to simplify Bag/Map framing, move Wonderbook navigation to page-edge index tabs and correct alignment of the existing in-game top HUD. This extension is presentation/layout only and must not reopen gameplay or the wider shell architecture.

WP18J must preserve the existing inventory, map topology, discovery, collection, progression, save and input behaviour established before this package.

## Visual authority

The approved visual direction established during the 2026-09-07 UI review remains authoritative:

- Bag: a magical satchel/saddlebag, using restrained leather, pocket, stitch, tag and compartment cues.
- Map: a bright magical quest/adventure map, using parchment, cartographic terrain, compass and trail cues.
- Wonderbook: a friendly enchanted story/spellbook, using a coherent open-book spread, visible binding, page-edge index navigation and subtle magical flourishes.
- Existing in-game HUD: concept-grade top navigation and status pills with clean, deliberate icon/text alignment.

The implementation should stay child-friendly, readable at first glance and consistent with the concept-grade WP18I visual language.

## Hard scope

### Bag

- strengthen the overall satchel/saddlebag silhouette;
- make pocket tabs read as attached labelled compartments;
- strengthen object slots without changing item hit targets or semantics;
- make the selected object unmistakable;
- visually link the selected slot to a dedicated treasure-tag detail area;
- retain food-use, Shop, quantity, scroll, pocket and Shimmer behaviour;
- simplify the decorative frame so borders do not cross, crowd or visually compete with actionable controls.

### Map

- use a parchment adventure-map surface;
- retain restrained terrain/cartographic texture and compass treatment;
- keep trail and node contrast readable while preserving the topology exactly;
- keep the current-location emphasis and homeward/nearby guidance intact;
- retain the existing physical/dotted-path semantics;
- simplify the decorative frame so header and close controls sit in clean space without border collisions.

### Wonderbook

- retain the strong outer cover, page stack, spine and two-page spread;
- move section navigation from top-floating buttons to filing/index tabs on the outer page edges;
- keep the spine visually clear at all times;
- make the active index tab read clearly as the current section;
- improve hierarchy between page headings, entry cards, stickers and badges;
- retain all section, filter, page-turn, close and portrait-companion behaviour;
- preserve the existing progress/collection model exactly.

### Existing in-game HUD alignment

- correct icon and label vertical alignment inside the existing top navigation buttons;
- normalise icon-to-label spacing across Map, Bag, Book and Settings;
- align the Shimmer and location pills to the same visual line/rhythm;
- preserve the existing HUD structure, button meanings, hit targets and interaction paths;
- do not redesign the shell beyond these alignment corrections.

## 2026-09-07 landscape-tablet remediation review

The first WP18J preview was reviewed on the target Galaxy Tab S8 in Chrome landscape. The user explicitly rejected approval and authorised an immediate remediation pass within this implementation.

### Confirmed Bag issue

The Bag concept is directionally improved, but its frame is overworked. Multiple decorative borders/stitch lines visually cross or crowd the top category controls and Close button, and lower framing sits too close to the Shop action. The result is busy rather than polished.

Required correction:

- reduce the frame to a cleaner outer magical shell plus one clear inner content frame;
- remove, soften or reposition decorative lines that collide with controls;
- establish a clean header zone for title, Close and Shimmer;
- keep category tabs on their own clean row beneath the header;
- give the Shop action clear breathing room from lower ornamentation;
- retain the satchel identity without decorative clutter.

### Confirmed Map issue

The Map content is broadly successful, but the modal frame has the same excessive-border problem as Bag. Decorative framing competes with the Close button, title area and map canvas.

Required correction:

- simplify the shell to one dominant outer frame and one inner parchment/content frame;
- keep parchment/cartographic treatment inside the content area;
- reserve clean header space for title/subtitle and Close;
- remove decorative lines that run behind or visually through actionable controls;
- preserve all map topology, route logic, labels and guidance exactly.

### Confirmed Wonderbook issue

The open-book treatment is approved directionally and should be preserved. The navigation is not. The current top-row section buttons float across the open spread, and the Places control visibly occupies the book spine.

Required correction:

- remove the top-floating section-button row;
- implement filing/index tabs down the outer edge of the book pages;
- ensure no index tab enters or crosses the spine;
- use an active-tab state so switching sections reads like skipping forward/backward through a physical book;
- preserve the existing section switching, filters, pagination, close behaviour and collection/progress semantics.

### Confirmed in-game HUD alignment issue

The existing concept-grade top HUD is functionally correct but the live landscape-tablet screenshot shows inconsistent visual alignment between icons and labels in Map, Bag, Book and Settings. The Shimmer/location status pills also need their internal and shared baseline alignment tightened.

Required correction:

- centre icons consistently within each navigation cell;
- place labels on a common baseline with consistent icon-to-label spacing;
- align Shimmer and location pills to the same top-row rhythm;
- preserve all current actions and hit targets;
- make no broader shell or control redesign as part of this correction.
