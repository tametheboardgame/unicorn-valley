# R6.5-WP18J - Bag, Map and Wonderbook Themed Polish Pass

## Objective

Take the three remaining major player-facing modal surfaces that still feel mechanically arranged rather than deliberately art-directed - **Bag, Map and Wonderbook** - and give each a final high-quality layout and themed presentation pass after WP18I.

This package exists because the WP18I exploration HUD and Settings work established a much stronger common UI language, but user review of the Bag, Map and Wonderbook screenshots showed that these three screens still suffer from inconsistent spacing, alignment, border density and insufficient individual identity.

The package must make all three feel like authored objects inside the Unicorn Valley world rather than generic panels using the same skin:

- **Bag** should feel like opening a magical satchel/saddlebag with pockets and stitched compartments.
- **Map** should feel like a magical quest/adventure map on parchment.
- **Wonderbook** should feel like an old enchanted spellbook/storybook with page markers, chapter tabs and an intentional open-book composition.

This is a **UI presentation-only package**. Existing inventory, map, discovery, collection, navigation and Wonderbook behaviour remain authoritative and unchanged.

## Hard scope boundary

### In scope

Only these three screens:

1. Bag / Inventory;
2. Map;
3. Wonderbook / Book.

Allowed work:

- alignment;
- spacing;
- panel proportions;
- visual hierarchy;
- modal shell/panel geometry;
- border simplification;
- shadows and depth treatment;
- themed decorative styling;
- tabs/category controls;
- close/back/previous/next/shop button presentation and placement;
- headers, subtitles, badges, labels and footer composition;
- icon presentation;
- readability and touch-target preservation;
- responsive behaviour across existing landscape tablet and desktop viewports;
- lightweight decorative vector/canvas details that do not materially inflate the application-entry budget.

### Explicitly out of scope

- Settings;
- exploration HUD;
- movement controls;
- contextual Talk/Enter/Start controls;
- race controls;
- Creator;
- Dialogue;
- Cottage decoration UI except where a shared primitive can be reused without changing its presentation;
- gameplay mechanics;
- inventory rules or item ownership;
- shop/economy behaviour;
- map discovery/progression logic;
- Wonderbook unlock/progression logic;
- quest logic;
- save schema;
- world geometry or collision;
- NPC placement or behaviour;
- new content;
- any R7 work.

Do not use this package as an excuse for another global modal rewrite. The target is exactly Bag, Map and Wonderbook.

## Shared quality contract

All three surfaces should still belong to the concept-grade WP18I family, but they should not look interchangeable.

Shared rules:

- generous negative space;
- clear top/header, content and footer zones;
- consistent safe margins;
- strong alignment grid;
- fewer nested borders;
- one dominant frame rather than frames inside frames inside frames;
- soft intentional shadows rather than duplicate shadows;
- readable child-facing typography;
- clear primary/secondary button hierarchy;
- visually stable layout on the Galaxy Tab S8 in landscape;
- mouse/keyboard desktop compatibility retained;
- no decorative element may interfere with hit targets, labels or scrolling;
- no styling may introduce horizontal/vertical browser-page overflow;
- hard 520 KiB application-entry budget remains unchanged.

## 1. Bag - Magical satchel / saddlebag identity

### Current issues to resolve

User review identified that the current Bag still feels like a generic modal with content boxes placed inside it:

- title, close button, category row and Shimmer/status elements do not sit on one clean grid;
- category tabs/pills feel loosely spaced rather than deliberately grouped;
- inventory and detail panes have unbalanced margins/gutters;
- the shop action does not feel anchored to a clear footer/action zone;
- small corner labels/tags can read as development leftovers;
- heavy nested borders and duplicated shadow language create visual clutter;
- the screen does not visually communicate "bag" strongly enough.

### Target identity

The player should feel as though she has opened a magical travelling satchel without turning the interface into a literal novelty illustration.

Preferred motifs:

- warm leather/suede/parchment-inspired framing within the existing pastel Unicorn Valley palette;
- stitched seams or dotted stitch lines used sparingly;
- pocket/compartment shapes for inventory groupings;
- small strap/buckle/tag cues around the frame or header where they improve identity;
- category tabs that resemble sewn labels or pocket tabs;
- item list/detail composition that reads as compartments inside one bag;
- Shimmer/currency presented as a small purse/tag/badge rather than a detached counter;
- Visit Shop action treated as a deliberate luggage/shop tag or footer action.

Do not:

- use photorealistic leather;
- make the panel dark/heavy;
- add so much stitching/buckle art that content becomes harder to scan;
- materially change item-list behaviour, selection or shop logic.

### Layout requirements

- establish one clean header grid containing title, category controls and close action;
- category tabs use equal visual rhythm and consistent active/inactive states;
- rebalance inventory pane and selected-item detail pane so neither feels cramped;
- use a consistent gutter between panes;
- keep scrollable item content clearly inside its own readable region;
- reserve a deliberate action/footer area for Visit Shop where applicable;
- no button or label should touch the outer frame or another control;
- no overlapping/gloss/shadow layers around category buttons.

## 2. Map - Magical quest/adventure map identity

### Current issues to resolve

User review identified that the Map needs the strongest composition cleanup:

- title/subtitle/map canvas/footer do not yet have clean spacing relationships;
- the map itself sits too close to surrounding explanatory text in places;
- footer/caption/legend information feels cramped;
- nested borders compete with the actual map;
- corner label treatment can look inherited from another modal rather than map-specific;
- current simple location circles/routes are functional but the surrounding presentation does not yet make them feel like a quest map.

### Target identity

The Map should feel like opening a magical quest/adventure chart.

Preferred motifs:

- parchment-like cream surface;
- softly irregular or rolled-map-inspired inner framing without sacrificing rectangular hit/layout geometry;
- compass rose or small compass-star motif;
- tasteful route/path flourishes;
- banner/ribbon treatment for subtitle or region legend where appropriate;
- illustrated-marker treatment around existing location circles without changing their authoritative location/discovery state;
- a more deliberate "You are here" marker;
- light cartographic marks such as mountains, trees, waves, crystals or stars where they can be generated cheaply and remain secondary to the actual map data;
- map-specific corner/legend language rather than reusing Bag tags.

The underlying map can continue to use simple circles/links for places. WP18J is not a map-content rewrite. The goal is to make those existing nodes feel like part of an intentional magical map.

### Layout requirements

- clear header zone with title and concise subtitle;
- one dominant map canvas with generous internal padding;
- map graphics centred and balanced inside the canvas;
- footer/legend separated clearly from the map drawing;
- no explanatory text colliding with route lines or markers;
- simplify outer/inner borders so the map is visually dominant;
- close/back controls aligned to the same safe-margin system as Bag/Book;
- map-specific decorative details remain behind or outside interaction labels and markers.

## 3. Wonderbook - Enchanted spellbook / storybook identity

### Current issues to resolve

User review identified that the Wonderbook is conceptually strong but visually over-framed and uneven:

- outer modal frame, inner frame and page borders compete with one another;
- category tabs across the top have inconsistent spacing and can feel like floating buttons rather than part of the book;
- the two-page spread is not always visually centred as one coherent object;
- Previous and Next feel detached from the book rather than integrated with page navigation;
- bottom status text, page numbers and Close the book action need stronger vertical rhythm;
- footer/scrapbook areas can feel slightly misaligned;
- the screen needs more unmistakable magical-book identity.

### Target identity

The Wonderbook should feel like an old but friendly enchanted spellbook/storybook.

Preferred motifs:

- warm parchment pages with subtle edge variation;
- richer magical-book outer frame/cover hints;
- central spine/gutter that makes the two pages read as a real spread;
- faint corner flourishes, stars, vines, moons, crystals or runic-looking decorative marks that are purely fictional/non-occult and child-friendly;
- chapter/category tabs that resemble ribbon bookmarks, page flags or enchanted chapter markers;
- Previous/Next controls integrated visually with page corners/edges;
- page numbers treated as part of the book rather than generic modal metadata;
- subtle magical glow/sparkle details used selectively;
- Close the book action styled as an intentional book closure/footer control.

Tone must be **whimsical enchanted storybook**, not dark, scary, horror, realistic occult or adult-fantasy grimoires.

### Layout requirements

- centre the complete two-page spread as a single composition;
- establish one dominant book frame instead of multiple equally strong outlines;
- use a consistent central gutter/spine;
- category/chapter tabs follow a deliberate equal rhythm and do not collide with title/frame;
- Previous/Next anchor clearly to left/right page navigation;
- page numbers align consistently;
- lower status/collection strip has enough breathing room;
- Close the book sits in a dedicated footer action area and does not compete with page controls;
- preserve all existing category/discovery/collection behaviour.

## Implementation approach

### J.1 - Screenshot-driven geometry audit

Using the latest user screenshots as defect evidence:

- record current coordinates/dimensions for title, close controls, tabs, main panels, footer/actions and scroll regions on all three screens;
- identify inconsistent margins, uneven gaps and nested frame layers;
- define a per-screen alignment grid before applying theme decoration.

### J.2 - Shared spacing and border simplification

- establish consistent outer safe margin, header spacing and footer spacing values;
- remove redundant nested borders and duplicate shadow layers;
- retain only borders that communicate hierarchy;
- ensure existing WP18I shared colours/button language remain recognisable.

### J.3 - Bag themed composition

- rebuild visible Bag composition around satchel/pocket visual language;
- align title, close action, tabs and counters;
- rebalance inventory/detail panes;
- add restrained stitch/pocket/tag details;
- relocate/retreat shop action into a deliberate action zone.

### J.4 - Map themed composition

- rebuild map frame/header/footer spacing;
- establish parchment/quest-map visual language;
- add restrained compass/cartographic motifs;
- improve current-location marker presentation without changing location logic;
- simplify borders and free space around the map itself.

### J.5 - Wonderbook themed composition

- establish one coherent open-book frame;
- integrate category tabs as chapter markers;
- align page spread, gutter, page numbers and navigation controls;
- apply child-friendly enchanted spellbook details;
- align footer/status/Close the book areas.

### J.6 - Device and evidence pass

Validate at minimum:

- Samsung Galaxy Tab S8 landscape reference presentation;
- 1280x720 desktop pointer presentation;
- 1280x800 landscape tablet;
- 1024x768 landscape tablet;
- 960x600 smaller landscape viewport.

Capture screenshots for:

1. Bag with a populated category and selected item;
2. Bag showing a category/tab change or longer item list;
3. Map in an established save with several discovered places;
4. Wonderbook main spread;
5. Wonderbook alternate category/page;
6. at least one smaller/narrower landscape viewport demonstrating containment.

## Acceptance criteria

### Shared polish

- obvious alignment and spacing defects from the user screenshots are removed;
- no overlapping controls/text;
- no clipped rounded corners;
- no duplicate/misaligned shadows;
- no modal content escapes its intended frame or scroll viewport;
- footer actions have clear reserved space;
- border density is visibly reduced;
- all three screens have balanced negative space;
- child-facing text remains readable at the reference tablet size.

### Bag

- unmistakably reads as a magical satchel/bag-themed interface;
- inventory and detail areas feel like coherent compartments;
- tabs look intentionally attached to the bag/pockets;
- Shimmer and Shop presentation feel integrated rather than floating;
- item behaviour is unchanged.

### Map

- unmistakably reads as a magical quest/adventure map;
- existing route/location information remains clearer than the decoration;
- map canvas has comfortable breathing room;
- title/subtitle/map/footer hierarchy is obvious;
- current-location presentation is clear;
- map discovery/travel behaviour is unchanged.

### Wonderbook

- unmistakably reads as an enchanted spellbook/storybook;
- two-page spread reads as one centred book;
- chapter/category tabs feel physically connected to the book;
- page navigation and Close the book controls feel intentionally placed;
- discovery/collection behaviour is unchanged.

### Technical

- project contract green;
- formatting/lint/type-check green;
- unit tests green;
- production build/static smoke green;
- hard 520 KiB application-entry budget remains unchanged and green;
- Chromium/Firefox/WebKit compatibility remains green;
- dedicated visual/layout regression coverage protects critical containment/alignment where practical.

## Human visual gate

WP18J requires a visual spot-check before it is considered complete.

The user should review the evidence/preview specifically for:

- overall premium quality;
- whether each surface now has the intended individual identity;
- alignment/spacing;
- border/shadow restraint;
- readability;
- whether theme decoration enhances rather than obstructs the screen.

If any of the three still feels like a generic modal with themed decorations pasted on top, the package is not complete.
