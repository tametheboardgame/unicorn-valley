# SH1.7 - Story House Illustrated Classics Consolidation

## Objective and boundaries

Close the already-delivered illustrated-classics programme without reopening accepted titles or redesigning the shared Story House reader. **Planned work, not yet executed.** The current published baseline is **17 books**. Alice, Peter Rabbit, Jemima Puddle-Duck and The Lantern at the Edge of the Woods have approved, merged illustration packages. This is a bounded transition into [SH2](R6.5-WP19SH2-STORY-HOUSE-LIBRARY-EXPANSION.md), not another feature-development pause for World and Just Games.

Own Story House-specific files, manifests, visual-bible documents and authoring guidance. Never alter World or Just Games implementation as routine cleanup. Isolate genuine shared-reader defects into separate remediation PRs.

## SH1.7A - Inventory and stale PR reconciliation

- Audit all published story manifests, generated catalogue entries, chapter/block IDs, edition and illustration-set relationships, progress and cover selection against current `main`.
- **Existing audit evidence (15 October 2026):** 17 catalogue titles, 316 referenced image paths and zero missing paths in the GitHub tree. Recheck before closing; this is static evidence, not a browser acceptance test.
- Inspect open legacy **PR #230** (Lion/Mouse original pilot) and **PR #261** (early Alice illustration planning). Main already contains restored Lion/Mouse art and Alice's completed programme via **PR #291**. Compare for genuinely unique material, record the disposition and close superseded branches/PRs without merging outdated content.
- Correct historic status for Lantern **SH1.8**, whose **PR #298 merged 10 October 2026**. Preserve stage-by-stage records as history; do not pretend they were never active.
- Record whether any separate actionable issues remain, with owner and bounded scope.

**Acceptance:** no required unmerged art/manuscript changes remain hidden in superseded PRs; audit and merge references are accurate.

## SH1.7B - Generated assets, manifests and Google Drive staging

- Inventory all generated WebPs and R4 manifests; distinguish working sources, active reader references, historical public-domain illustrations and genuine orphans.
- Initial inventory flags **one unused WebP in its book manifest**: `public/stories/alices-adventures-in-wonderland/illustrations/generated/alice-cover-cropped.webp`, with `generated-assets/manifests/story-alices-adventures-in-wonderland-cover.json`. Check repository-wide references, catalogue and history before proposing removal; do **not** delete merely because the book manifest does not reference it.
- Check whether older Lion/Mouse cover assets are an explicit human-approved cover exception under the newer reuse-reader-image rule; do not silently rewrite approved art.
- Examine Drive staging residue and document candidates for eventual tidy-up. **No bulk Google Drive deletion or destructive external action without explicit further approval.**
- Verify the permanent **Google Drive -> WIF -> GitHub Actions -> WebP** workflow still accepts a controlled source replacement without credentials or manual GitHub binary upload.

**Acceptance:** no broken image references, no historical art loss, no unjustified source or rights deletion, and a tested/verified replacement procedure.

## SH1.7C - Rights, metadata and editorial standards

- Review rights/provenance for source wording, source translation, edition, historic illustrations, new generated illustrations, catalogue covers and publication markets **independently**.
- Resolve incomplete/unknown rights metadata for **The Duck Bread Baker**, checking author permission and picture-art provenance rather than automatically claiming rights.
- Reconcile `docs/story-library-authoring.md` with the **shipped** modern-cover convention: select an approved reader image after its batch is accepted; no baked-in title; preserve a Classic cover where legitimate; dedicated generated cover is an explicitly approved exception only.
- Preserve rights-verification evidence and record any unavailable source as a blocker, not an assumed grant.
- Document reusable character/location anchors, image density, stable block mapping, responsive crops, in-place replacement, visual acceptance and edition-selection conventions.

**Acceptance:** source and asset metadata is defensible, and the authoring runbook agrees with actual implemented behaviour.

## SH1.7D - Targeted regression and documentation close-out

- Regenerate/check `public/stories/catalogue.json` from a fresh-main integration branch; do not manually merge away other content.
- Run relevant catalogue/unit/reader/browser coverage for title discovery, modern/classic cover/illustration selection, editions, saves/resume, lazy loading and representative phone/tablet/desktop reader use; scope additional tests to the actual diff.
- Apply existing rapid-draft validation and exact-head final Merge Gate policy; do not expand Chromium shards or restart the engineering improvement programme.
- Update the SH1 canonical programme record, stale SH1.2B title-access status, high-level roadmaps and Story House stream-local record at actual handover. **Product stream must not independently overwrite `AGENTS.md`, `STATUS.md` or `PROJECT_STATE.json`**; integration owner reconciles root state at the appropriate checkpoint.

**Acceptance:** relevant tests green, no changed reader behaviour or lost save data, documentary history and stream ownership reconciled.

## SH1.7E - Final handover

- Mark SH1.7 and parent SH1 **complete** only after A-D have recorded review evidence, any explicit cleanup approval and final PR merge.
- Link a real merge SHA and CI/preview checks. The next active Story House package becomes **SH2.0**, not an ambiguous open-ended SH1 continuation.
- Keep World and Just Games development free to proceed in their own short-lived branches throughout this bounded exercise.

## Non-goals

No new title, no rerecording of accepted books, no blanket art regeneration, no shared-reader rewrite, no production deployment, no unreviewed external deletion.
