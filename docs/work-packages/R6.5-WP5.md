# R6.5-WP5 - Moonflower Glade and Cottage Depth

## Objective

Make Moonflower Glade, the Hollow Tree promise and Moonflower Cottage materially richer, more interactive and visibly personal over time, so home feels like a place worth returning to rather than mainly a route into the wider valley.

## Context / Why

R6 established a polished and usable baseline, but the R6.5 breadth audit identified home and the Glade as needing more curiosity, revisit value and visible evidence of the player's wider adventures.

The canonical package definition remains in `docs/07V-R6.5-VALLEY-COMPLETENESS-BREADTH.md`. Relevant content targets also come from `docs/07W-R6.5-CONTENT-BLUEPRINT.md` and the accepted project UX/art/system contracts.

Active delivery is PR #125 on branch `r6.5-wp5-glade-cottage-depth`.

## Dependencies

- R6.5-WP2 - Ambient Population and World Interaction Toolkit: complete.
- R6.5-WP3 - Economy and Reward Loop Completion: complete.
- R6.5-WP4 is merged and forms the current `main` baseline, although it is not a formal dependency for this package.

## Scope

- Pay off the Hollow Tree as a real secret/micro-location or equivalent authored destination.
- Add additional Glade interactions around stream, bridge, flowers/garden and discoveries.
- Support visiting residents where it improves the home-region sense of life.
- Show achievements, ribbons, treasures or discoveries at home where practical.
- Add tactile Cottage interactions beyond decoration placement controls.
- Add at least one substantive Glade-centred story/quest.
- Add at least one separate Glade secret chain.
- Add persistent visual changes tied to progress.
- Add new decoration/display rewards connected to wider R6.5 content/economy.
- Preserve mobile/touch-safe exploration and existing accessibility behaviour.
- Add automated regression/browser coverage for durable rules and critical interaction flows.

## Non-goals

- Do not implement the full future gardening system.
- Do not begin R6.5-WP6 Meadow/Run expansion inside this package.
- Do not redesign global movement, save architecture or interaction systems unless a defect makes a minimal compatible fix necessary.
- Do not perform production deployment.
- Do not broaden the package into a general art/polish pass across unrelated regions.

## Invariants / Frozen Baseline

- Existing R0-R6 progression remains playable.
- R6.5-WP1 through WP4 content and economy/resident contracts remain compatible.
- Existing save data continues to load.
- Child-first controls, low reading burden and no-pressure design remain intact.
- Touch controls and mobile layouts remain first-class.
- Reusable content/services should be preferred to one-off scene hacks.
- `main` remains releasable.

## Implementation Guidance

- Continue using the established quest, discovery, world-flag, reward, interaction and save authorities rather than inventing parallel state systems.
- Keep new interactions legible without requiring long text explanations.
- Reuse production assets and established visual language.
- Ensure persistent feedback is meaningful but not visually noisy.
- Preserve the existing package branch and PR history.

## Acceptance Criteria

- The Hollow Tree promise has a real gameplay payoff.
- The Glade offers multiple optional curiosity interactions beyond simply travelling through it.
- At least one substantive Glade story/quest is playable and persistent.
- At least one separate secret/discovery chain is playable and persistent.
- Returning home after meaningful progress shows visible evidence of player accomplishments/world change.
- Cottage interaction extends beyond decoration placement in a child-readable way.
- New rewards connect to the established item/economy/home systems.
- Save/reload preserves all new durable state.
- Mobile/touch use remains safe and understandable.
- No regression is introduced into prior R6/R6.5 progression.

## Technical Validation

Required before technical completion:

```sh
npm run validate
```

And GitHub CI on the final package head must pass:

- `Validate`
- `Browser playtest`
- `Browser compatibility`

Run focused/targeted tests during implementation as useful, but the final CI matrix is the package technical gate.

## Human Acceptance

Human acceptance is required after technical validation because this package changes the visual/experiential quality of the home region and child-facing interaction density.

The reviewer should inspect at minimum:

- Hollow Tree Nook readability and delight;
- whether new Glade interactions feel discoverable rather than cluttered;
- whether persistent home displays/changes feel rewarding;
- Cottage interaction clarity on mobile;
- whether the package still feels calm and child-first.

Technical success does not automatically release this gate.

## Risk / Backout

Primary risks are save-state regression, interaction clutter, mobile target conflicts and visual drift. Normal Git/PR rollback is sufficient provided no incompatible save schema change is introduced.
