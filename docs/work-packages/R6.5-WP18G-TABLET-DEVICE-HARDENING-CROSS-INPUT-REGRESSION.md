# R6.5-WP18G - Tablet Device Hardening and Cross-Input Regression

## Objective

Harden the completed WP18 tablet-first experience across realistic landscape tablet shapes and secondary desktop/browser inputs before returning to human replay.

The Samsung Galaxy Tab S8 remains the reference human device, but implementation must not be hard-coded to that model.

## Device/layout matrix

At minimum validate representative landscape viewports for:

- 16:9;
- 16:10;
- 4:3;
- smaller landscape Android tablet dimensions;
- larger landscape tablet dimensions;
- desktop/laptop browser.

Where Playwright/device emulation cannot reproduce a browser-specific touch behaviour faithfully, document the gap and require targeted real-device evidence on the Galaxy Tab S8.

## Touch/browser hardening

Verify:

- no required action triggers Chrome long-press context/navigation UI during normal use;
- `touch-action`, pointer event handling and selection behaviour are appropriate for game controls;
- pointer cancel/leave/focus loss cannot leave movement or Gallop/Run stuck;
- simultaneous touch interactions behave predictably;
- tap-to-move remains responsive around UI controls;
- accidental page scroll/zoom/selection is prevented where appropriate without breaking scrollable modals;
- safe-area insets and viewport changes do not hide controls;
- orientation changes fail gracefully even if landscape is the intended mode.

## Layout/readability hardening

Across the matrix verify:

- no major shell overlap;
- no text overflow outside intended containers;
- no control hidden beyond viewport bounds;
- scrolling modals remain scrollable;
- contextual action remains visible without covering critical content;
- race track/obstacles remain readable ahead of the player;
- Bag/Map/Creator/category layouts scale without collapsing;
- text remains child-readable at effective rendered size.

## Input regression

Preserve secondary support for:

- keyboard movement and shortcuts where still intentional;
- mouse click-to-move;
- mouse/pointer interaction with buttons/modals;
- desktop race controls;
- text entry in creator without movement-key interception.

Tablet-first must not become tablet-only unless an explicit later product decision says so.

## Performance and resilience

Re-run:

- standard validation;
- production build/static smoke;
- hard 520 KiB application-entry gate;
- Chromium full playthrough/regressions;
- Firefox/WebKit compatibility where supported;
- performance/frame diagnostics in representative heavy scenes;
- WP18B freeze stress cases after all later UI/world changes.

The final WP18 code must not reintroduce the freezes while solving layout problems.

## Evidence

Capture enough automated and visual evidence to show:

- reference landscape tablet shell;
- race controls with unobscured track;
- inventory with more than six items;
- map open state;
- creator category state;
- representative dialogue/interaction;
- desktop compatibility.

## Acceptance

WP18G is complete when the tablet-first UI is robust across the agreed viewport matrix, the Galaxy Tab S8-specific browser interaction risks are covered by code plus targeted real-device checks where needed, desktop secondary inputs remain functional, freeze regressions remain closed, and all technical/performance gates are green.
