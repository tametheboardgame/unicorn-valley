# R6.5-WP18G - Tablet Device Hardening and Cross-Input Regression

## Objective

Harden the completed WP18 tablet-first experience across realistic landscape tablet shapes and secondary desktop/browser inputs before returning to human replay.

The Samsung Galaxy Tab S8 remains the reference human device, but implementation is not hard-coded to that model.

## Delivered

- Added explicit canvas browser-gesture hardening: `touch-action: none`, selection/callout suppression and page overscroll suppression without globally disabling DOM input or scrollable modal behaviour.
- Made `TouchMovementPad` presentation refreshable so live landscape/portrait/orientation changes rebuild the correct controls instead of retaining the construction-time layout.
- Movement/Gallop input is released before presentation replacement, preventing an orientation change from leaving held movement behind.
- Wired the touch presentation refresh into the existing exploration-shell refresh path rather than adding a second timer or input architecture.
- Added a representative landscape viewport matrix covering 16:9, 16:10, 4:3, smaller tablet and larger tablet shapes using rendered browser-space target sizes.
- Added containment and size checks for the exploration shell, movement/Gallop controls, Bag, Map and progressive Creator controls.
- Added race-layout coverage proving RUN/JUMP remain large at the edges while preserving a clear central track corridor.
- Added live landscape -> portrait -> landscape recovery coverage.
- Added secondary desktop regression coverage for click-to-move, creator text entry and desktop race mode.
- Extended browser compatibility coverage with a WP18G health/containment smoke across Chromium, Firefox and WebKit.
- Retained the existing WP18B long-session freeze suites, simultaneous touch race coverage, save recovery, performance diagnostics and full historical browser regression suite as mandatory gates.

## Device/layout evidence

Automated coverage validates:

- 1280x720, 16:9 landscape;
- 1280x800, 16:10 reference-style landscape;
- 1024x768, 4:3 landscape;
- 960x600 smaller landscape tablet;
- 1600x1000 larger landscape tablet;
- 1280x720 desktop with touch disabled;
- live 1280x800 -> 600x900 -> 1280x800 orientation/presentation cycling.

The automated matrix verifies no page overflow, contained canvas/shell controls, browser-space touch target sizes, race control placement, Bag/Map/Creator containment and desktop fallback behaviour.

## Real-device boundary

Playwright can validate pointer/touch layout, multi-touch semantics and browser gesture policy, but cannot faithfully reproduce every Chrome/Android long-press, OS navigation, palm/contact or physical-comfort behaviour of the Samsung Galaxy Tab S8.

Those remaining device-specific questions are intentionally transferred to `R6.5-WP18H`, which is the real Galaxy Tab S8 human replay gate. WP18G does not claim simulated browser evidence is a substitute for that session.
