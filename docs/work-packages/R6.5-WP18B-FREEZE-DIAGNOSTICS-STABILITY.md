# R6.5-WP18B - Freeze Diagnostics, Root Cause and Stability

## Objective

Treat the observed hard freezes as release-blocking defects. Build enough runtime evidence to identify the actual failure mode, reproduce each known freeze, fix root causes, and add durable regression/stress coverage before control-shell implementation proceeds.

## Known human-observed failures

1. Full freeze during normal play in Hollow Tree Nook / Tree Nook.
2. Full freeze during normal play in Twinkle and Thread.
3. Repeatable Sunlit/Starlight Beach failure when opening the Bag: most of the world disappears, then the game becomes unusable.

The package did not assume these shared one cause.

## Delivered diagnostics

The existing `BrowserDiagnostics` path now exposes a bounded rolling health record when `?diagnostics=1`, including:

- active and registered Phaser scene lifecycle state;
- frame heartbeat, recent frame samples and long-frame summary;
- game-object, timer and tween counts per scene where available;
- last meaningful pointer/keyboard interaction;
- last runtime error or unhandled rejection;
- renderer context-loss/restoration state;
- browser memory signals where exposed safely;
- early installation so extended/lazy scene registration failures can be observed.

The record is deliberately bounded and is not active during ordinary production play.

## Root-cause finding

A concrete deterministic Bag crash path was identified in long-running saves. Save reconciliation deliberately preserves legacy/retired inventory IDs, while `InventoryService.listOwnedItems()` previously called `itemRegistry.get()` for every saved ID. A retired ID could therefore throw while the Bag was being built.

Bag enumeration now ignores retired/unknown IDs while normal active inventory operations remain strictly validated. Unit and real browser regressions cover this path.

## Lifecycle hardening

Bag and Shop modal close paths now resume their paused return scene before stopping the modal. This removes fragile stop-before-resume sequencing shared by the Beach Bag and Twinkle & Thread flows.

This is defensive lifecycle hardening. It is not recorded as a proven explanation for every human-observed freeze.

## Stress evidence

Exact-head Chromium validation on `12bd3090c7a1e73f3ae1d308e8adeefa2dbbb811` completed the full 153-test suite with **150 passed and 3 intentionally skipped**.

The WP18B regressions all passed:

- Starlight Beach: 10 repeated real Bag open/close cycles, followed by responsive movement and healthy diagnostics;
- Starlight Beach stale save: a deliberately injected retired inventory ID survives reload, Bag open/close and subsequent movement;
- Hollow Tree Nook: 8 repeated Nook entry, Bag open/close, movement and return cycles with bounded lifecycle counts;
- Twinkle & Thread: 8 repeated Shop -> Bag -> interior-resume cycles with bounded lifecycle counts and safe return to the village.

Across these exercised flows there were no recorded runtime errors, unhandled rejections or renderer-context loss, the Phaser heartbeat remained live, and object/timer/tween counts did not show unbounded accumulation attributable to the remediated lifecycle.

Two earlier CI failures during this work were investigated with traces and were confirmed to be wall-clock test-budget expiries while the scenes remained active and healthy. Their coverage was not weakened; the affected repeated stress cases retained all cycles and were given sufficient time to complete.

The exact original daughter-playtest sequence for the Tree Nook and Twinkle freezes was not independently reconstructed. WP18B therefore does not claim those historical freezes were individually reproduced. Instead, the common lifecycle was hardened and the relevant real flows now survive repeated stress with diagnostic evidence.

## Acceptance evidence

WP18B acceptance is satisfied because:

- the deterministic retired-item Bag failure is fixed and regression-covered;
- the repeatable Beach Bag flow survives repeated real cycling and remains playable;
- Hollow Tree Nook and Twinkle & Thread survive repeated realistic modal/scene lifecycle stress;
- no unhandled runtime exception/rejection remains in the exercised flows;
- lifecycle counts remain bounded in the stress cases;
- normal validation, production build, static smoke and the unchanged **520 KiB** application-entry budget are green;
- Chromium/Firefox/WebKit compatibility is green;
- the full exact-head Chromium playtest is green;
- no human gate is required for this technical package.

WP18H remains the required real-device human replay before WP17 can reconsider R7 readiness.
