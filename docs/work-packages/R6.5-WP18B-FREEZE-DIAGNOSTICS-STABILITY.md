# R6.5-WP18B - Freeze Diagnostics, Root Cause and Stability

## Objective

Treat the observed hard freezes as release-blocking defects. Build enough runtime evidence to identify the actual failure mode, reproduce each known freeze, fix root causes, and add durable regression/stress coverage before control-shell implementation proceeds.

## Known human-observed failures

1. Full freeze during normal play in Hollow Tree Nook / Tree Nook.
2. Full freeze during normal play in Twinkle and Thread.
3. Repeatable Sunlit Beach failure when opening the bag: everything except the sand disappears, then the game freezes.

Do not assume these share one cause. Do not classify them as generic "performance" problems without evidence.

## Investigation questions

For each freeze determine whether the game is:

- blocking the JavaScript main thread;
- still rendering but no longer receiving input;
- unintentionally paused behind a launched/failed scene;
- trapped in a scene-transition lifecycle;
- accumulating duplicate managers/listeners/timers/tweens;
- failing a lazy-load/dynamic-import path;
- suffering runaway object creation or memory pressure;
- losing WebGL/canvas state;
- throwing an unhandled runtime exception;
- entering an invalid save/world state;
- or failing in another reproducible way.

## Diagnostics work

Extend existing browser diagnostics rather than building a disconnected debug framework.

Capture a bounded rolling record sufficient to reconstruct the lead-up to failure, including where practical:

- active Phaser scenes;
- scene start/launch/pause/resume/sleep/wake/stop/shutdown transitions;
- previous and current world scene;
- inventory/shop/modal launch and close events;
- dynamic-import/extended-scene registration success/failure;
- frame heartbeat and recent long-frame summary;
- current game object counts per active scene;
- active timer/tween counts or equivalent bounded lifecycle signals;
- current input button/axis state;
- last meaningful player interaction;
- recent save/write operation status;
- last caught runtime error/rejection;
- renderer/context-loss signals where exposed;
- browser memory signals only where safely and reliably available.

Diagnostics must remain bounded and must not themselves create a memory leak or materially distort normal performance.

## Reproduction work

Build deterministic or semi-deterministic regressions for the known cases where practical.

### Sunlit Beach bag case

This is the strongest initial target because it is repeatable.

Automate or manually drive:

1. enter Sunlit Beach through the real player path;
2. reach a stable playable state;
3. open the Bag using the same tablet-facing entry route;
4. verify the world remains rendered correctly behind/around the modal as intended;
5. close the Bag;
6. verify the player can continue moving/interacting;
7. repeat multiple times.

The regression must fail on the known broken behaviour, not merely assert that `InventoryScene` can be launched in isolation.

### Tree Nook and Twinkle and Thread

Recreate realistic entry/exit/re-entry and interaction sequences, including repeated visits and modal interactions. If the exact original sequence cannot initially be reproduced, use the new diagnostics during targeted manual/automated stress runs until the failure is explained.

## Stress matrix

At minimum exercise:

- repeated region transitions;
- repeated interior/shop entry and exit;
- repeated Bag open/close;
- repeated Wonderbook open/close;
- shop transactions;
- cottage decoration open/close;
- race entry/exit/retry;
- repeated NPC interactions;
- tap-to-move while entering/leaving interaction range;
- scene pause/resume cycles;
- browser focus loss and restoration where automation supports it;
- a sustained continuous-play run long enough to expose lifecycle accumulation.

## Fix rules

- Fix root causes, not symptoms.
- Do not simply restart the game after a freeze and call that resilience.
- A graceful recovery path may be added as defence in depth, but it does not replace fixing a deterministic defect.
- Do not disable features or remove content solely to make the stress suite pass unless the user explicitly approves that product trade-off.
- Preserve save compatibility and the 520 KiB entry budget.

## Acceptance

WP18B is complete when:

- the repeatable Sunlit Beach Bag freeze is no longer reproducible;
- Tree Nook and Twinkle and Thread failures have either been reproduced and fixed or their root cause has been convincingly identified and eliminated through the common failing lifecycle;
- no unhandled runtime exception/rejection is left in the exercised flows;
- repeated modal/scene transitions remain playable after stress cycles;
- long-session diagnostics show no obvious unbounded lifecycle accumulation attributable to the remediated systems;
- new regressions cover the human failure modes where practical;
- normal validation, browser compatibility and the hard 520 KiB entry budget remain green.
