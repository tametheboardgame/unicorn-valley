# R6.5-WP18E - Bag, Map, Creator and Modal Tablet UX

## Objective

Apply the approved landscape-tablet design language to inventory, map access, unicorn creator and the major modal/menu surfaces so they scale beyond initial content counts and remain clear, readable and touch-friendly.

## Design authority

Use the approved WP18A concepts for Bag/Map and Unicorn Creator. Reuse the interaction hierarchy, typography, spacing and touch-target principles established by WP18C.

## Bag/inventory redesign

The current six-item visibility ceiling is a functional usability defect and must be eliminated.

Implement a scalable inventory model/presentation with:

- explicit item categories/pockets justified by current content;
- at minimum a sensible treatment for Food and Quest Items, with additional categories only where useful;
- scrolling within growing lists;
- readable item name, icon/visual, quantity/state and relevant action;
- obvious selected-item state;
- clear close/back behaviour;
- no reliance on tiny pagination controls;
- touch-safe scrolling that does not accidentally trigger item use;
- support for inventories substantially larger than six items.

### Food use

Food should no longer be a dead inventory object.

Design and implement a bounded first useful food interaction consistent with the approved concept and existing game balance. The playtest hypothesis of temporary effects such as a short speed boost is a candidate, not a mandatory exact implementation.

Requirements:

- tapping/selecting food clearly exposes what can be done;
- consuming food visibly changes inventory state;
- any gameplay effect is understandable and time-bounded where appropriate;
- quest-critical items cannot be accidentally consumed;
- save/state behaviour is deterministic.

## Map access

Provide a distinct, obvious Map action from the exploration shell.

The map should:

- be easy to open and close by touch;
- prioritise current location and meaningful destinations;
- avoid being conflated with Bag or Wonderbook navigation;
- use labels/icons that remain readable at tablet scale;
- preserve discovery/progression rules rather than revealing content that should remain hidden.

This package does not require a total world-map redesign unless the approved concept demonstrates it is necessary.

## Unicorn creator redesign

Replace the cramped all-at-once control presentation with progressive disclosure.

Expected structure should support categories such as:

- Main;
- Colours;
- Mane & Tail;
- Horn;
- Markings;
- Accessories.

Only the active category should expose its detailed controls. Preserve a large unicorn preview and make swatches/options touch-sized and visually recognisable.

Also revalidate:

- naming input;
- keyboard/input focus isolation from game controls;
- re-editing an existing unicorn;
- confirm/cancel/reset behaviour;
- text wrapping and control collision at landscape tablet sizes.

## Other modal surfaces

Audit and reconcile the major child-facing overlays with the same design rules, prioritising surfaces implicated by playtest clutter/overlap:

- Wonderbook;
- shop screens;
- settings/help;
- dialogue/story panels;
- cottage decoration;
- activity instructions/results;
- race result/entry modals where not already handled.

Do not perform a cosmetic rewrite of every panel. Fix hierarchy, overflow, touchability and consistency where the existing surface violates the tablet-first contract.

## Layout rules

- no unintentional text overflow;
- no overlapping controls;
- scrollable content must visibly afford scrolling;
- large text should not force controls off-screen without a scroll/flow strategy;
- close/back action placement should be consistent;
- modal launch/close must preserve input state and scene stability;
- gamepad/keyboard/mouse secondary support should not compromise touch layout.

## Acceptance

WP18E is complete when inventories larger than six items remain fully accessible, Food has a meaningful safe use path, Map is a distinct usable system entry, Creator follows the approved progressive landscape-tablet layout, and the audited modal surfaces meet the shared readability/overflow/touch contract.
