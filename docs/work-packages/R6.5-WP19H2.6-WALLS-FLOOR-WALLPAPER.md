# R6.5-WP19H2.6 – Walls, Floor & Wallpaper

**Status:** In progress

**Parent package:** R6.5-WP19H2 – Moonflower Cottage & Home Customisation

**Previous checkpoint:** H2.5 Decorate Mode Foundation, human-approved 18 September 2026.

## Purpose

Add curated, persistent cottage surface styling without creating a second home-state system. Wall colour, wallpaper and flooring become named home-style choices that can later participate in the H2 unlock/reward framework.

## Implementation decisions

- Extend the versioned save schema with a dedicated `home.style` state rather than using world flags. Schema v4 stores `back`, `left`, `right` and `front` walls independently, each with its own colour and wallpaper.
- Use stable named IDs for wall colour, wallpaper and floor style.
- Introduce one canonical cottage style catalogue containing visual metadata and starter availability. The editor reads directly from these catalogues and paginates automatically, so later colours, wallpapers and floors can be added without redesigning the UI.
- Keep starter choices curated and child-readable; unrestricted RGB editing is out of scope.
- Resolve missing/retired style IDs safely to canonical defaults at presentation time without destroying unknown future state.
- Render cottage walls, wallpaper and flooring from the persisted style state at the canonical room-surface owner.
- Decorate mode gains a dedicated fixed `Room Style` action above-left of the Decorate/Done control; it is not represented by a blue world placement spot and remains absent from normal play.
- The room-style editor follows the Unicorn Designer interaction model: Walls / Wallpaper / Floor category tabs with directly tappable visual swatches, plus Back / Left / Right / Front wall selectors for wall colour and wallpaper, and a live room preview before `Apply Style` persists the combined selection.
- Returning from the style editor restores Decorate mode.
- H2.7 furniture finishes will extend the same home-style persistence model rather than inventing another one.

## Starter catalogue target

- Wall colours: Moon Cream, Blush Dawn, Misty Lilac, Sea Glass and Buttercup.
- Wallpaper: Plain, Moon Sprigs, Star Scatter and Meadow Vines.
- Flooring: Honey Oak, Rosewood, Whitewashed Oak and Lavender Boards.

## Acceptance criteria

- Existing schema-v1/v2 saves migrate safely to the new current schema. Schema-v3 saves copy their existing room-wide wall colour/wallpaper onto all four walls during v4 migration, preserving appearance while enabling later independent changes.
- New saves contain explicit home-style state.
- Normal cottage rendering reflects independently persisted back, left, right and front wall colour/wallpaper IDs plus the room-wide floor ID.
- Decorate mode exposes a fixed Room Style button beside the decorate controls; normal play does not, and room surfaces never masquerade as placeable-object spots.
- The style editor exposes Walls, Wallpaper and Floor as explicit categories with visible swatches rather than next/previous cycling. Walls and Wallpaper additionally expose Back, Left, Right and Front/Door selectors, and the selected wall is highlighted in the preview.
- Back/cancel returns without changing persisted style.
- Apply persists the complete preview state.
- Different styles can be applied to all four walls simultaneously, and the full combination survives room exit/re-entry and a fresh save-service/browser reload.
- Unknown style IDs never crash room rendering and fall back visually to canonical defaults.
- No permanent surface choice is stored in `world.flags`.

## Human gate

Change all three surface categories, apply the style, leave and re-enter the cottage, then reload/continue. Confirm the exact wall colour, wallpaper and flooring persist and that the editor is visually clear on the reference tablet.


## Human feedback refinement – 18 September 2026

The first H2.6 playtest passed persistence, rendering and migration behaviour. David requested two UX refinements before accepting the checkpoint:

- move room surface styling out of the blue in-world placement-marker language and into a fixed button above-left of Decorate/Done;
- make the room-style editor behave more like the Unicorn Designer, with category tabs and visible swatches instead of sequential Previous/Next controls.

These refinements are part of H2.6 rather than a new work package.


## Four-wall extensibility refinement – 18 September 2026

Following the successful initial H2.6 playtest, H2.6 was extended before H2.7 so the permanent surface model would not need another migration later:

- back, left, right and front/door walls are independent saved surfaces;
- each wall has its own colour and wallpaper;
- floor remains room-wide;
- schema v4 migrates the prior single-wall v3 selection onto all four walls;
- wall/wallpaper/floor choices are generated from the canonical catalogues;
- the swatch grid automatically pages after eight entries, so adding future catalogue choices does not require a new layout;
- the preview highlights the wall currently being edited.
