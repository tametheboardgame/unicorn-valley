# R6.5-WP19H1.9 - Interaction, Feedback and Dialogue Remediation

Approved from David's Moonflower Glade tablet review on 15 September 2026. This was a bounded remediation checkpoint inside H1, not a new area redesign.

## Completion state

**Completed and human-approved on 15 September 2026.** Delivered outcomes include:

- the first green tutorial sparkle uses the shared explicit `Pick up` interaction and hands off to one blue return-to-Pip guidance card without a competing Wonderbook discovery toast;
- physical H1 collectables use the shared explicit pickup language instead of proximity auto-collection, and persistent object-name labels were removed;
- transient-notification ownership prevents dialogue, guidance, Wonderbook/reward feedback and quest-complete feedback from stacking over one another;
- Pip's closing trail conversation completes before the centred `Quest Complete` presentation appears;
- ordinary dialogue uses stable geometry through Continue/Done progression;
- the guidance-card icon has a dedicated gutter and no longer overlaps its leading text;
- supporting-resident portrait framing/centring was corrected at the shared owner;
- shared camera/presentation stability improvements were applied without integer-snapping deliberately smooth NPC/fish/world motion;
- targeted regression coverage was updated to describe the approved explicit-interaction and feedback sequencing.

The H1.9 visual/tablet gate is closed. Later H1.11 work preserved these semantics while consolidating ownership and removing legacy compatibility specific to Moonflower Glade.

The H1.9 candidate substantially improved the first-time Pip flow, tablet dialogue presentation and tutorial sparkle clarity, but the review exposed several shared interaction/feedback inconsistencies. These were fixed at canonical shared owners so the result became the normal game language rather than a collection of Moonflower-only exceptions.

## Product intent

The player should learn one consistent rule for collectible objects and one consistent rule for transient feedback:

- if something in the world can be collected, approach it and explicitly use a `Pick up` interaction;
- the world should not show permanent object-name labels merely to explain what can be collected;
- only one non-dialogue notification/guidance surface should own the player's attention at a time;
- dialogue owns the lower-screen/modal presentation while active;
- quest completion feedback happens after the closing conversation, never on top of it;
- dialogue geometry remains stable through a conversation and portraits are visually centred;
- static world/UI presentation remains visually stable while the camera/player moves, without quantising deliberately smooth NPC/environment animation.

## H1.9A - Green tutorial sparkle hand-off

The first green Moonflower Sparkle must no longer produce the generic Wonderbook discovery notification as its primary feedback.

Required behaviour:

- collect the green sparkle through the intended tutorial collection path;
- suppress the generic `new discovery for your Wonderbook` notification for this moment;
- show one blue guidance card after collection;
- guidance should clearly direct the player back to Pip, e.g. `Now go back and talk to Pip.`;
- no competing Wonderbook toast may appear over or immediately alongside that guidance;
- the sparkle remains visually green/distinct from ambient gold Glade sparkles.

## H1.9B - Canonical explicit pickup interaction

Create or extend one shared pickup interaction pattern for world collectables.

Required behaviour:

- collectables do not auto-collect merely because the player crosses their radius;
- when the player enters a generous valid interaction radius, the normal shared interaction button appears;
- the action label is exactly `Pick up`;
- keyboard, controller-equivalent and touch activation routes through the normal interaction system;
- clicking/tapping a collectable may select/approach it using the existing shared approach behaviour, but collection still requires the explicit `Pick up` action;
- collection is idempotent and cannot award the same unique object twice;
- once collected, the object and its pickup interaction disappear immediately and persist correctly through save/reload.

Apply this shared pattern to at minimum:

- Pip trail Silver Feather;
- Warm Moon-Moss;
- Tiny Starry Tracks/egg-trail collectable objects where they are actual pickups rather than purely visual clues;
- Willow's three special Moonflowers;
- Wonderbook world collectables/discoveries that represent physical pickup objects;
- other equivalent world collectables discovered during the implementation audit.

Do not convert ordinary scenery interactions, NPC Talk, doors/gates or non-collectable discoveries into `Pick up`.

## H1.9C - Remove persistent collectable labels

Persistent world labels such as `Silver Feather` and `Warm moon-moss` are no longer required once the interaction prompt communicates the action.

Required behaviour:

- remove persistent name labels from H1 collectable objects;
- preserve enough visual distinction that the object itself remains discoverable;
- use a generous interaction radius so the player does not need pixel-perfect positioning;
- ensure scenery/bridges cannot obscure required interaction information because required interaction information now lives in the shared interaction UI rather than a world label.

## H1.9D - Global transient-notification ownership

Establish one shared rule for non-dialogue transient UI so notifications cannot stack over one another.

Priority/ownership requirements:

1. Active dialogue/modal UI has highest ownership and blocks ordinary transient notifications from rendering over it.
2. Explicit blue guidance cards outrank generic Wonderbook/discovery toasts.
3. Quest-completion presentation outranks generic reward/discovery toasts while it is active.
4. Lower-priority notifications should either be suppressed when redundant or queued for later when they still add information.

Specific acceptance:

- a blue guidance card and a Wonderbook notification are never visible simultaneously;
- generic Wonderbook feedback cannot appear over dialogue;
- generic reward/helped-the-valley feedback cannot appear over dialogue;
- duplicated messages describing the same event should be suppressed rather than queued;
- queued independent feedback should display only after the higher-priority owner releases the presentation slot.

This should be implemented at the shared feedback/presentation owner where practical, not by adding one-off hide calls to Moonflower Glade.

## H1.9E - Quest completion after closing dialogue

Remove the current `You helped and the valley remembers` style prompt from the Pip return conversation flow.

Required sequence:

1. Player returns to Pip after completing the mysterious trail.
2. Pip's complete closing conversation plays with no reward/completion UI layered over the dialogue card.
3. The dialogue closes.
4. Only then show a short centred quest-complete presentation.

Preferred presentation:

- concise `Quest Complete` burst/card in the centre of the playable area;
- optional quest name beneath if it remains visually clean;
- short-lived, non-blocking and consistent with the game's established UI language;
- no simultaneous generic `valley remembers`, Wonderbook or reward toast for the same completion event.

The quest state/rewards must still complete exactly once even if the player skips/closes dialogue through supported controls.

## H1.9F - Stable dialogue geometry by gameplay mode

The shared DialogueCard must use stable dimensions within each supported gameplay presentation rather than resizing between lines of the same conversation.

Required behaviour:

- desktop/landscape dialogue uses one fixed panel geometry for ordinary line dialogue;
- tablet/touch landscape uses one fixed panel geometry appropriate to the available viewport;
- portrait/mobile mode uses its own fixed safe geometry where applicable;
- moving between Continue and Done states must not materially change panel height/width;
- short text leaves intentional breathing room rather than shrinking the panel;
- longer text wraps within the fixed text region;
- choice layouts may use their defined expanded geometry, but must remain stable within that mode and not jitter line-to-line;
- touch controls remain hidden while modal dialogue owns the lower area, as already accepted in the current H1.9 candidate.

The two Pip screenshots from the 15 September tablet review are the visual regression reference: the smaller and larger variants should converge to one intentional tablet dialogue size.

## H1.9G - Speaker portrait centring

Fix Juniper's portrait alignment inside the circular dialogue frame and audit the shared portrait placement so this is not a Juniper-only offset patch.

Required behaviour:

- visual subject, not merely raw texture bounds, reads centred inside the portrait circle;
- Juniper no longer appears shifted down/sideways in the portrait frame;
- Pip and representative supporting residents remain correctly framed;
- wide tails/ears/horns are not clipped by the correction;
- portrait placement remains consistent across fixed dialogue panel modes.

If character-specific portrait focus metadata is genuinely required because silhouettes differ, expose it as explicit reusable presentation metadata rather than scattering positional magic numbers through DialogueCard.

## H1.9H - Final tablet review: completion, guidance spacing and visual stability

David's follow-up tablet review on 15 September confirmed the explicit green-sparkle and Moonflower pickup flow is substantially clearer, but identified three final shared issues.

### Pip return completion

The return-with-egg Pip conversation must advance the final `talk-to-character` quest step only when the closing dialogue completes. That progression must then allow the existing shared quest-completion presenter to show its centred `Quest Complete` feedback after the dialogue disappears.

### Guidance-card icon gutter

The decorative star in the shared blue guidance card must own a dedicated left-hand gutter. Guidance text must be laid out inside the remaining content region, so short leading words such as `Pip` can never overlap the star.

### Whole-game visual stability audit

Visual vibration/jitter while the player or camera moves is a shared presentation defect, not an object-by-object styling issue.

Required approach:

- retain whole-pixel final camera rendering for exploration cameras;
- do not repeatedly re-rasterise unchanged Phaser text or redraw unchanged fixed icons every frame;
- round final presentation-only screen/camera-derived positions where fractional movement can create a one-pixel shimmer;
- keep semantic interaction/world coordinates unchanged;
- do not snap deliberately smooth NPC, fish, follower or other authored world animation to integer simulation positions merely to hide rendering artefacts;
- preserve existing NPC collision separation/hysteresis and include close-pass movement in the visual review so collision does not present as shaking;
- check representative static scenery, collectables, interaction affordances, fixed HUD/navigation, guidance/reaction cards, dialogue, supporting residents and ambient moving life during camera movement.

The intent is stable rendering without converting smooth motion into stepped motion.

## Acceptance criteria

H1.9 remediation was accepted after all of the following were met:

- green sparkle collection shows one blue return-to-Pip guidance card and no generic Wonderbook toast;
- Silver Feather and Warm Moon-Moss show `Pick up` through the shared interaction button when the player is within a forgiving radius;
- those objects do not auto-collect merely through proximity;
- persistent `Silver Feather` / `Warm moon-moss` labels are gone;
- Willow's special Moonflowers use the same explicit pickup language;
- representative physical Wonderbook collectables use the same explicit pickup language;
- only one transient non-dialogue notification owns the screen at a time;
- blue guidance blocks/suppresses competing generic Wonderbook feedback;
- no reward/discovery/completion prompt appears on top of dialogue;
- Pip's closing conversation completes first, followed by a centred `Quest Complete` presentation;
- the blue guidance star has a dedicated gutter and never overlaps guidance text;
- Pip's dialogue panel does not change size between lines/Continue/Done within tablet landscape mode;
- dialogue geometry is stable in representative desktop and supported touch modes;
- Juniper is visually centred in the speaker portrait and representative other portraits remain correct;
- static world/UI elements do not visibly vibrate while the player/camera moves;
- interaction prompts and affordances do not re-rasterise/redraw unchanged presentation every frame;
- deliberately moving NPCs/ambient life remain smooth rather than becoming integer-snapped/stepped;
- close-pass NPC/player movement does not reproduce the previously observed shake behaviour;
- collection/quest progression remains idempotent and save-compatible;
- targeted tests and the relevant build/type/lint checks pass;
- stale browser tests that encoded intentionally superseded H1 behaviour were updated truthfully rather than worked around in production code.
