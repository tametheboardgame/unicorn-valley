# R6.5-WP19H0.5 - Home Screen Final Polish

Added by David on 13 September 2026 as the required first screen-level polish package after R6.5-WP19H0 and before the area-by-area R6.5-WP19H1-H13 programme.

The purpose of this package is to treat the home screen as the first part of the final screen-by-screen polish phase rather than skipping directly into playable areas. The intent is to sort the home screen comprehensively before Moonflower Glade begins.

The WP19H0 performance/loading contract remains authoritative. Home-screen polish must preserve startup discipline, save compatibility, accepted audio behaviour and existing progression semantics unless a bounded correction is explicitly approved.

## Governing principle

The first stage is David's human review, not agent-led redesign.

David reviews the released/candidate home screen on:

- laptop/desktop;
- tablet;
- phone.

He records everything he wants improved before implementation begins.

## Mandatory five-stage contract

### Stage 1 - Human review

David reviews the current home screen across laptop/desktop, tablet and phone and records all desired improvements, defects and visual opportunities.

The review may include:

- background artwork and composition;
- Unicorn Valley title/logo presentation;
- Continue/New Game and other button hierarchy;
- button layout, sizing, styling, spacing and interaction states;
- settings access and supporting controls;
- animation and motion;
- music/audio presentation;
- responsive behaviour and safe areas;
- readability, accessibility and focus states;
- visual polish, charm and consistency with the approved game UI direction;
- any other home-screen-specific issue David identifies.

#### Recorded review - 13 September 2026

David approved the following home-screen direction after reviewing the current candidate:

- replace the text title lock-up with a proper transparent Unicorn Valley logo including the tagline;
- remove the old title-panel shadow/backplate behind that logo;
- give the logo a restrained grow/move entrance rather than leaving it completely static;
- remove the retired procedural title background from the runtime entirely so it cannot flash before the generated artwork arrives;
- make Home Settings launch the exact same reusable Settings experience used by the rest of the game, then remove the title-specific settings implementation;
- rebuild the options card with rounded corners, layered shadows, subtle surface texture/shading and more deliberate button depth;
- size the card from the actions actually available: first-run players see only New Game and Settings, while returning players additionally see Continue and My Unicorn;
- preserve a clear primary action while removing unexplained typography inconsistencies and dead space;
- make phone portrait a deliberately art-directed composition rather than a clipped landscape canvas;
- keep tablet and small-screen landscape presentations visually consistent with the same title-screen design language;
- add a restrained sparkle-shower layer over the scenic artwork but behind the logo and options UI;
- preserve reduced-motion behaviour, touch target sizing, safe areas and keyboard interaction;
- preserve New Game, Continue, save and progression semantics.

David approved the generated logo and the first logo-integration checkpoint before the wider remediation began.

### Stage 2 - Home-screen audit

After David's review, inspect the current home-screen implementation technically and visually. Reconcile his feedback with:

- layout/composition and hierarchy;
- responsive behaviour on laptop/tablet/phone;
- typography and visual consistency;
- input, focus, hover/touch and accessibility behaviour;
- save/Continue state handling;
- settings/audio integration;
- startup/loading behaviour and WP19H0 performance budgets;
- lifecycle/object health;
- existing automated coverage and any missing regression protection.

The audit may identify additional local issues, but must not discard or dilute David's feedback.

#### Audit findings - 13 September 2026

The implementation audit found that:

- the desktop card used a fixed 520 px height, so the first-run two-action state inherited substantial empty space;
- title buttons and the card still used the earlier flat rectangle treatment instead of the canonical rounded UI primitives/tokens;
- the title scene still owned a duplicate Settings overlay and duplicated audio/accessibility state handling even though `AudioSettingsPanel` and `SettingsScene` already provide the canonical reusable flow;
- the portrait DOM shell used the portrait artwork as a texture inside a menu box rather than treating the whole viewport as a composed title screen;
- the portrait shell duplicated the obsolete title-specific Settings UI;
- the small-screen landscape path relied on the scaled 1280x720 canvas, leaving touch controls physically undersized on phones;
- the generic input hint was visually weak and did not adapt to the actual input method;
- automated tests still encoded the retired procedural-background fallback and old title-specific Settings implementation.

### Stage 3 - Remediation

Implement the agreed home-screen tightening.

This is a comprehensive polish pass, not merely bug fixing. Mild visual redesign is explicitly allowed where justified by the review, including layout changes, improved artwork treatment, stronger button hierarchy and presentation improvements.

Preserve accepted saves, Continue semantics, progression, settings behaviour and audio unless this package explicitly owns a bounded correction.

#### Implementation checkpoint - 13 September 2026

Current branch implementation now includes:

- the approved transparent logo asset and entrance motion, with reduced-motion bypass;
- complete removal of the retired procedural title artwork and old title lock-up code;
- preload of the generated title derivatives and logo before TitleScene to avoid the old-art flash;
- an intrinsic desktop options card whose height follows the two-action or four-action state;
- canonical rounded panel/button primitives, layered shadows, restrained surface texture, stronger primary-action hierarchy and a compact status treatment;
- removal of the low-value generic input hint;
- keyboard Up/Down menu selection while retaining the existing Interact/Enter activation path;
- Home Settings routed through `AudioSettingsPanel` into the canonical `SettingsScene`, with the title-owned Settings overlay and duplicated preference logic removed;
- a full-viewport touch title composition with the real logo and art-directed generated background;
- dedicated portrait treatment for phone/tablet and a compact small-screen landscape treatment with minimum 48 px touch actions;
- an ambient sparkle layer behind the logo/card on both canvas and touch-DOM presentations, with reduced-motion handling;
- updated historical regression tests plus a new H0.5 responsive evidence suite covering fresh/returning desktop, tablet portrait, phone landscape and reduced motion.

### Stage 4 - Cross-device validation

Re-test the completed home screen on laptop/desktop, tablet and phone. Add targeted automated regression and representative responsive visual evidence for changed behaviour.

Do not consider the package complete because one desktop screenshot looks correct.

The H0.5 branch is now in automated qualification. Representative screenshots are produced by `tests/play/r6.5-wp19h0.5-home-screen-polish.spec.ts`. Human visual review remains required after the branch preview updates.

### Stage 5 - Human acceptance

David reviews the finished home screen and explicitly accepts or rejects the package.

Do not close or progress into R6.5-WP19H1 until David has accepted the home-screen result.

## Exit criteria

R6.5-WP19H0.5 is complete only when:

- David's cross-device review has been recorded;
- the agreed home-screen remediation is implemented;
- laptop/tablet/phone validation is complete;
- relevant automated regressions are green;
- WP19H0 performance/loading constraints remain satisfied;
- David explicitly accepts the finished home screen.

R6.5-WP19H1 begins only after this package is complete and accepted.
