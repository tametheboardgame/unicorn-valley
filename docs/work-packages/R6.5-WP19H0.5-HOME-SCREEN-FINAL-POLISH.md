# R6.5-WP19H0.5 - Home Screen Final Polish

Added by David on 13 September 2026 as the required first screen-level polish package after R6.5-WP19H0 and before the area-by-area R6.5-WP19H1-H13 programme.

The purpose of this package is to treat the home screen as the first part of the final screen-by-screen polish phase rather than skipping directly into playable areas. The intent is to sort the home screen comprehensively before Moonflower Glade begins.

The WP19H0 performance/loading contract remains authoritative. Home-screen polish must preserve startup discipline, save compatibility, accepted audio behaviour and existing progression semantics unless a bounded correction is explicitly approved.

## Governing principle

The first stage is David's human review, not agent-led redesign.

David reviews the released/candidate home screen on:

- laptop/desktop;
- tablet;
- phone.

He records everything he wants improved before implementation begins.

## Mandatory five-stage contract

### Stage 1 - Human review

David reviews the current home screen across laptop/desktop, tablet and phone and records all desired improvements, defects and visual opportunities.

The review may include:

- background artwork and composition;
- Unicorn Valley title/logo presentation;
- Continue/New Game and other button hierarchy;
- button layout, sizing, styling, spacing and interaction states;
- settings access and supporting controls;
- animation and motion;
- music/audio presentation;
- responsive behaviour and safe areas;
- readability, accessibility and focus states;
- visual polish, charm and consistency with the approved game UI direction;
- any other home-screen-specific issue David identifies.

### Stage 2 - Home-screen audit

After David's review, inspect the current home-screen implementation technically and visually. Reconcile his feedback with:

- layout/composition and hierarchy;
- responsive behaviour on laptop/tablet/phone;
- typography and visual consistency;
- input, focus, hover/touch and accessibility behaviour;
- save/Continue state handling;
- settings/audio integration;
- startup/loading behaviour and WP19H0 performance budgets;
- lifecycle/object health;
- existing automated coverage and any missing regression protection.

The audit may identify additional local issues, but must not discard or dilute David's feedback.

### Stage 3 - Remediation

Implement the agreed home-screen tightening.

This is a comprehensive polish pass, not merely bug fixing. Mild visual redesign is explicitly allowed where justified by the review, including layout changes, improved artwork treatment, stronger button hierarchy and presentation improvements.

Preserve accepted saves, Continue semantics, progression, settings behaviour and audio unless this package explicitly owns a bounded correction.

### Stage 4 - Cross-device validation

Re-test the completed home screen on laptop/desktop, tablet and phone. Add targeted automated regression and representative responsive visual evidence for changed behaviour.

Do not consider the package complete because one desktop screenshot looks correct.

### Stage 5 - Human acceptance

David reviews the finished home screen and explicitly accepts or rejects the package.

Do not close or progress into R6.5-WP19H1 until David has accepted the home-screen result.

## Exit criteria

R6.5-WP19H0.5 is complete only when:

- David's cross-device review has been recorded;
- the agreed home-screen remediation is implemented;
- laptop/tablet/phone validation is complete;
- relevant automated regressions are green;
- WP19H0 performance/loading constraints remain satisfied;
- David explicitly accepts the finished home screen.

R6.5-WP19H1 begins only after this package is complete and accepted.
