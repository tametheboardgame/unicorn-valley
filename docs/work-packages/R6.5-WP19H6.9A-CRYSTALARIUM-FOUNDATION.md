# H6.9A — Crystalarium musical gate: first-round rules and architecture

**Decision:** approved 22 October 2026. This package is **design and pure-rules foundation only**, not a playable minigame, unlocked Grotto, registered scene or release. It is stacked on H6.7B PR #332 until the World stream's pending PR #331/#332 prerequisites are integrated. Do not start H6.9B runtime/quest mutations or merge dependent branches ahead of those gates.

## Player experience and physical placement

**Narrative:** Echo has found a crystal instrument built into the sealed Crystal Grotto arch. The crystals answer one another with pitches; matching the right pairs makes the doorway resonate. The opening is one joyful **30–60-second target experience**, with no actual gameplay timer or failure deadline. It is a meaningful, very short tutorial to a much larger, optional **Crystalarium** after unlocking the door.

**Door sequence:** meet/talk to Echo → approach a visibly sealed but readable arch → select **Play opening melody** → one small three-note merge board → three correct resonances → visible/heard magical opening → safe return outside the arch → normal **Go inside** action. Once opened, the door stays open on future visits. Offer **Play Crystalarium** as a *separate optional* action at an authored instrument/nursery position, not a competing prompt over **Go inside**. Never replay the opening gate compulsorily.

**Inside:** preserve the existing CrystalGrottoScene and its independently discoverable broad blue low-note, slim aqua bright-note and tiny lavender bell-note crystals. The intro melody **does not grant** those three internal discoveries or the Echo Crystal Chime reward. The later full game uses the **same `crystalarium` family and shared merge rule**, not a second mini-game.

## Locked first-round mechanics

| Attribute | Contract |
| --- | --- |
| Canonical family | `crystalarium`, exactly one mini-game catalogue ID and one gameplay scene |
| Variants | `opening-melody` (story-world intro, hidden from Just Games); `resonance-patterns` (full replay, visible in Just Games) |
| Intro board | Fixed **4 columns × 3 rows**; six tier-0 crystals and six empty sockets, no random spawns |
| Three pairs | Two **low**, two **bright**, two **bell** (three distinct shapes/colours) |
| Required pattern | **low hum → bright ping → soft bell**, exactly three successful merges |
| Matching | Choose/drag one crystal onto another of the **same family and tier** anywhere on the board; no adjacency rule |
| Merge result | Consumes exactly the source piece; upgrades the destination piece to the next tier; emits a corresponding sound and visual pulse |
| Wrong merge | Wrong family, unequal tier, empty/same cell or out-of-order pair: no consumption, no flag, no progress |
| Completion | Exactly one opening result after the third successful merge; no replay requirement to enter |
| Rescue | **Reset** restores all six original pieces; invalid attempts are non-destructive and the board cannot softlock |
| Presentation | A three-slot visible melody strip, labelled crystal glyphs, coloured facet families and relative pitch. Never rely on colour or sound alone |
| Controls | Tap source then destination, click or drag; keyboard arrows to select cell and Enter/Space to pick/merge, Escape to cancel; mobile landscape touch targets |
| Assistance | Echo's instruction remains available, with optional context hint; mistakes produce a gentle indication of which note to play, not a penalty |
| Limits | No lives, energy, timeouts, monetary pressure, consumables, score requirement or random puzzle failure |

The prototype rule contract is under `src/game/minigames/crystalarium/CrystalariumOpeningRules.ts`. It has **no Phaser dependencies, clock, RNG, storage, side effects or quest imports**. `combineCrystalPieces()` deliberately works beyond the introductory first tier; H6.9B/C must re-use it (or refactor to a demonstrably equivalent shared core) rather than fork gameplay logic.

**Visual/audio vocabulary:** blue round crystal `●` / *Deep hum*; aqua diamond `◆` / *Clear ping*; lilac star `✦` / *Soft bell*. Each has both glyph+text+colour, and all notes must be accompanied by motion/contrast and a visible completion track. Sound uses the existing project audio architecture; do not create a competing WebAudio manager or require generated voice/music before the prototype. Volume and muted play must remain effective. The introduction's three-tone melody is an *outer-door instrument*, distinct from the already-existing inside-Grotto note discoveries.

**Deterministic solvability evidence:** the pure engine starts with three disjoint legal pairs and only accepts the pair corresponding to the next expected note. For each pair the player can select source/destination in either order. Every valid path therefore has exactly three accepted merges; **all 2³ = 8 possible legal action paths finish**, with no way to consume a future note early. A Vitest exhaustive tree covers all legal states and invalid attempts. UI movement/pointer selection remains an H6.9B browser responsibility.

## Shared mini-game platform readiness (H6.8 verified for authoring)

MG-WP0–MG-WP4 are documented as implemented in `MINIGAMES-ROADMAP.md` and `docs/architecture/MINI-GAME-PLATFORM.md`; live code inspection confirms:

- `MiniGameCatalogue.ts` is the single family/variant metadata owner. **Do not add `crystalarium` to the catalogue in H6.9A**: no gameplay `SceneManifest` registration exists yet. H6.9B–D will add the catalogue and manifest registration together, maintaining their referential-integrity tests.
- `MiniGameLauncher.ts` and `MiniGameSession.ts` supply `launchMiniGame`, source-aware `world`/`just-games` context, variant, return target and side-effect policy. No direct scene import/add/launch or hard-coded return.
- `MiniGameOutcomeGateway.ts` supplies `runMiniGameAdventureEffect(session, effect, apply)`. **Caveat:** this utility permits `null` sessions for older callers. The Crystalarium *world-unlock adapter* must also explicitly require a valid `session` with `source === 'world'`, `sideEffectPolicy === 'world'`, `gameId === 'crystalarium'`, `variantId === 'opening-melody'` and a Grotto `worldContext.interactionId`; never trust a `null` session. Revalidate outcome ownership on delivery.
- Main-world story and doorway code owns the narrative, locations, locked/unlocked presentation and SaveService/QuestEngine effects. The **mini-game gameplay scene** owns only matching, sequence and result, never the adventure save.
- `JustGamesScene` launches **only `resonance-patterns`** through the catalogue. Just Games is sandboxed, so a full-game win must never alter any world, quest, inventory, Shimmer or unlock state.
- `returnFromMiniGame()` follows an explicit session target. World launches should safely resume the Brook scene with the player at `CRYSTAL_BROOK_GROTTO_THRESHOLD.returnPosition`, which must not overlap the threshold trigger. Restart/retry cannot cause a scene-launch loop.
- The architecture requires world-first games to reach **a single playable, catalogue-exposed implementation** before final adoption. H6.9B/C prototypes are incremental draft milestones; the final H6.9 programme cannot merge incomplete before H6.9D integration.

## Quest index-preserving change and legacy saves

**Current implementation, verified:** `CrystalGrottoStoryService.talkToEcho()` starts `quest:echo-crystal-song`; `QuestEngine.processAutomaticSteps()` advances `unlock chamber` step **0** immediately, then `set-world-flag open` step **1** and `set-song-active` step **2**, arriving at `low/bright/bell` discovery steps **3/4/5**. Thus *talking to Echo opens the door immediately*.

**H6.9B must change the canonical quest definition, as a single intentional migration:**

| Step index | Existing | Proposed H6.9B |
| --- | --- | --- |
| 0 | Unlock chamber discovery | **Keep**: introduce/discover the sealed Grotto location |
| 1 | Set Grotto-open flag automatically | **Replace with** `unlock-discovery:crystalarium-opening-resonance`, which only a qualifying first world win can issue |
| 2 | Set Crystal Song active flag | **Replace with** existing `set-world-flag:CRYSTAL_GROTTO_OPEN_FLAG = true`, processed immediately after step 1 completes |
| 3, 4, 5 | Discover low, bright, bell notes | **Keep same step IDs and order** |
| 6 onwards | Complete song, active flag off, completion/glow/reward | **Keep same step IDs, records and rewards** |

The original **song active flag** set at index 2 must instead be set by the song-start domain service (`talkToEcho`) after starting the quest (or an equivalently tested world service). In `talkToEcho()`, *active step 1* must now produce clear “play the entrance instrument” dialogue; do not default to the old bell-note instruction. H6.7B's new moving Echo conversation is the sole story activation surface. No new save-schema field/version is required for the preferred implementation: the new intro completion is a registered discovery, and the door still uses its pre-existing `CRYSTAL_GROTTO_OPEN_FLAG`.

**H6.9A's pure legacy predicate** `getGrottoGateAccess()` recognises existing open flag, completed quest, owned Crystal Chime, glowing grotto or a legacy active quest already at any of steps 3–10. A current/new quest at step 1 or 2 without the opening evidence remains sealed. This is *read-only*: no opening or quest writes happen in H6.9A. For H6.9B, explicit, idempotent reconciliation may restore the existing open flag for an inconsistent old save; preserve the active/current quest step and never award a reward twice. In particular, **do not** automatically award opening discovery in Just Games or jump an active note-stage quest backwards to the tutorial.

**Success transaction in H6.9B:** gameplay reports a verified completed intro result to the world-qualified outcome adapter → adapter validates session/variant/world context, checks current gate once more → `runMiniGameAdventureEffect` invokes the **existing** `DiscoveryService.unlockDiscovery` for new intro resonance → QuestEngine advances index 1 and executes index 2 (sets old Grotto-open flag) → animated doorway reacts → return to safe Brook position. If a completion callback is repeated, subsequent calls must be no-ops. Invalid, abandoned, cancelled, sandbox or mismatched-variant results make **zero** persistent changes.
