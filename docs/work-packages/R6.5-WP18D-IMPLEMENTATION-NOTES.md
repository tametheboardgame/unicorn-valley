# R6.5-WP18D Implementation Notes

## Scope completed

R6.5-WP18D remediates the concrete functional defects captured by the WP17 human playthrough without widening into the later tablet-modal or world-art packages.

## Mandatory defect evidence

### Echo interaction

- Root cause: the Crystal Brook Echo bridge created visual presentation only and did not participate in the shared interaction authority.
- Fix: Echo now uses `AmbientPopulationWorldManager` through `R6_AMBIENT_RESIDENT_PLACEMENTS`.
- Direct tap and contextual E/Enter interaction both resolve through the same `activateResident` authority.
- The obsolete Echo bridge startup path was removed. Fern was moved to the same shared runtime while that duplicate path was being removed.

### Moonflower Cottage collision

- Root cause: furniture had collision, but the room perimeter did not.
- Fix: explicit top, left, right and bottom wall colliders now close the visible room boundary while preserving the intended exit approach.
- Regression coverage asserts the lower boundary behind the exit is blocked and the exit approach remains walkable.

### Cottage decoration state

Authoritative rule:

- inventory quantity is ownership authority;
- placing an owned decoration does not consume it from inventory;
- placed quantity may not exceed owned quantity;
- replacing or clearing a slot changes placement only;
- a single owned copy moves between slots rather than duplicating;
- multiple placements are allowed only when multiple copies are owned;
- legacy saves with more placements than owned copies are normalised by removing excess placements without changing owned quantity or save schema.

Regression coverage exercises placement, removal, multi-copy placement and legacy over-placement repair.

### Maple discoverability and progression

- Root cause: Maple's ambient village route was remote from the bakery despite her content and quest identity being bakery-centred.
- Fix: Maple now follows a reachable bakery-approach route with increased interaction priority/radius, preserving exploration without adding a permanent quest marker.

### Purchase feedback

- General shop purchases now distinguish first ownership from repeat purchases and state item acquired, Shimmer spent and remaining balance.
- Bakery purchases already produced a success message and remaining balance, but repeatable stock redrew exactly as before after purchase. The persistent card state now includes the owned quantity (`×1`, `×2`, etc.), so a croissant/bun purchase visibly changes the stock immediately while repeat purchasing remains available.
- Bakery regression coverage verifies first and second repeat purchases, item quantity, price, remaining Shimmer and persistent visible ownership state.

### Reward feedback

- Economy reconciliation now emits a single `SHIMMER_REWARDED` event when new rewards are actually claimed.
- Shared reward feedback shows the amount earned and resulting balance, avoiding a second popup when nothing changed.

### Point-and-click facing regression

- Root cause: facing followed each small pathfinding waypoint, so obstacle routing could alternate direction presentation rapidly.
- Fix: movement velocity still follows the safe A* path, while facing authority follows the final clicked destination.
- Existing click-navigation browser regression remains part of the full playtest suite.

### Placeholder/icon-over-character regressions

Classification after re-audit:

- intentional map/UI icons and small-world interaction symbols remain intentional UI affordances;
- the legacy Sunbeam Village Willow/Marigold/Pebble marker circles and prototype icons are technical presentation fixtures that are retained only as hidden topology fixtures;
- production character sprites remain the visible world representation for those NPCs;
- no new incorrect world-character placeholder was introduced by WP18D.

The existing `r6-wp6.18f-npc-marker-cleanup` browser regression remains authoritative for the hidden legacy circles/icons and visible production sprites/name labels. The WP18D automated village capture also shows production character art without the reported circles over those characters.

## Validation notes

The first fully formatted WP18D head passed contract validation, formatting, lint, type-check, unit tests, production build, performance budget, static smoke and the browser compatibility matrix. Its browser playtest had one existing performance-guard failure: Rainbow Meadow settled p95 measured 187.2 ms against a 180 ms runner-baseline guard. All generated functional playtest scenarios passed with zero errors and zero warnings. This result is treated as a CI performance variance unless repeated on the final head.

The final head must pass exact-head CI before merge. WP18D has `human_gate: none`, so no manual approval stop is required once final automated validation is green.
