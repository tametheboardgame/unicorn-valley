## Scope and execution contract audio integration and authoring guide

Autonomy: Green bounded wiring; David approves subjective soundtrack/mix. Dependencies: WP19G and WP19D/E event semantics.

Scope:

- Wire existing SFX intents: UI select/back, Talk acknowledgement, collection, discovery, quest completion, friendship, doors, decoration, race countdown/go/jump/boost/impact/finish.
- Bind optional object sounds by stable interaction ID, for example a crystal note, mushroom cue or door creak. Trigger on successful action, not every frame near an object.
- Rate-limit repetitive effects and avoid double sounds from overlapping scene/event listeners. Keep speech cues quiet; duck music only where listening tests justify it.
- Separate ambience loops from one-shot effects, with clean start/stop ownership. Do not infer loop behaviour from the filename alone.
- Establish a gain/mix pass across uploaded files and inspect audible seams; do not promise gapless MP3 loops without testing the actual files.
- Write `docs/AUDIO-UPLOAD-GUIDE.md` with the two folders, naming examples, assignment examples, supported formats, useful track lengths, how to replace a file and how to report desired event bindings.
- Maintain a clear “missing final asset / fallback / assigned and tested” checklist. If no user music is supplied, complete and test infrastructure with a small fixture, leaving final selection explicit rather than claiming bespoke scoring complete.

## Human-review remediation accepted into scope on 12 September 2026

The first WP19H preview exposed continuity/settings defects. These are now part of the package acceptance contract rather than deferred polish:

- If the resolved music track does not change when moving between scenes/locations, the existing playback must continue from its current position. Do not restart the same track merely because the Phaser scene changed.
- In **Chosen track** mode, location changes must not replace or restart the selected track. The chosen track remains continuous until the user changes mode/track, mutes music or playback is otherwise deliberately stopped.
- In **Scene music** mode, moving to a genuinely different contextual track must transition with a short crossfade rather than a hard cut/restart. Moving between scenes mapped to the same track remains seamless.
- Music settings use one mode control: **Scene music / Chosen track**. The track picker is visible only in Chosen track mode.
- Master/music/ambience/effects volume controls use real sliders rather than click-to-cycle rows.
- The title screen is assigned `music:title/01-the-four-note-path`; where browser autoplay policy prevents immediate playback it must start/resume on the first valid user gesture without losing the title music context.
- Opening/closing Settings, Inventory, Map or Wonderbook must not unnecessarily reset the current music context.

Done when the above continuity/settings behaviour is technically verified, music persists across modals, effects fire once at the intended moment, mute always works, uploaded-file instructions require no code knowledge and David has completed the subjective soundtrack/mix review. Backout: mapping-only revert where possible; no game progress is affected.

## Performance finding and successor package

WP19H exposed that the current whole-game 650 KiB gzip safety envelope is no longer an appropriate long-term growth model because it sums all emitted JavaScript, including lazy/on-demand chunks. **Do not use WP19H as the place to redesign that policy.** Finish WP19H functionally and preserve its existing technical guardrails for this delivery.

After WP19H is accepted, the mandatory next package is `R6.5-WP19H0 - Performance Architecture and Codebase Consolidation`. H0 owns the measured bundle/startup audit, deliberate code-splitting, dead/duplicate/legacy cleanup and replacement of the whole-game ceiling with scalable startup/first-playable/lazy-chunk budgets plus total-size trending. WP19H1 cannot start until H0 is accepted.
