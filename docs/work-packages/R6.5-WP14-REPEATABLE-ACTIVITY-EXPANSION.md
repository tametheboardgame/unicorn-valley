# R6.5-WP14 - Repeatable Activity Expansion

## Goal

Create credible non-racing ways to spend a short play session repeatedly, bringing the valley to at least three replayable non-racing activities including Firefly Lantern.

## Canonical source

This package implements the WP14 section of `docs/07V-R6.5-VALLEY-COMPLETENESS-BREADTH.md` and must preserve the R6.5 economy, mobile-accessibility and performance contracts.

## Starting baseline

Accepted `main`: `3db374dd48445386819d1da97d4367619f7b9cef` (R6.5-WP13 merge).

The audit confirms two intentional foundations already exist:

- Sunbeam Bakery already contains Maple's Wobbly Cake design hook and explicitly states that the repeatable baking table belongs to later R6.5 work.
- Starlight Beach already contains Coral's beachcombing basket, but it currently produces only rotating observation text and one first-use Wonderbook discovery rather than a real activity loop.
- Firefly Lantern remains the existing completed repeatable non-racing activity.
- `SaveGame.activities.miniGameRecords` is already generic and can record additional activity best results without a schema migration.

## Delivery contract

### 1. Maple's repeatable Bakery activity

Upgrade the existing Wobbly Cake promise into a short touch-first baking/decorating activity after Maple's first cake story is complete.

Required characteristics:

- no timer or fail state;
- at least three meaningful touch choices/steps rather than one button producing a result;
- child-readable visual feedback and short instructions;
- several finite recipe/design outcomes worth replaying to discover;
- best/progress state saved through `activities.miniGameRecords` and existing collection/memory state;
- first-completion reward integrated through the existing Shimmer reward authority;
- replay must not become repeatable Shimmer farming;
- returns cleanly to Sunbeam Bakery and preserves all existing shop/story behaviour.

### 2. Coral's Beachcombing activity

Replace the shallow basket interaction with a real short beachcombing/tide-pool observation activity.

Required characteristics:

- no timer or fail state;
- large touch targets and simple instructions;
- several beach observation spots/finds in each run;
- explicitly nature-friendly framing: observe living creatures, do not remove them;
- finite Wonderbook/collection outcomes across replay;
- best/progress state saved through the existing activity record authority;
- first-completion reward integrated through the existing Shimmer reward authority;
- no repeatable currency farming;
- returns cleanly to Starlight Beach and preserves WP9-WP13 story/race/world-state behaviour.

### 3. Shared progression and economy rules

- Reuse `activities.miniGameRecords`, collection memories/discoveries, `ShimmerEconomyService` / economy reward policy and existing save service.
- No save-schema change unless a genuine blocker is proven.
- No daily/real-world timers, streak pressure or FOMO.
- No mandatory activity completion for core progression.
- Activity rewards should create curiosity and recognition, not grind loops.
- An optional Pebble making/display activity may be added only if the two required activities are complete, fully validated and the extra scope remains genuinely small.

### 4. Loading and presentation

- Keep new activity presentation lazy/on-demand so the 520 KiB application-entry hard cap remains unchanged.
- Reuse established production UI patterns and touch target sizing.
- Activity scenes/overlays must be safe on desktop, tablet and mobile layouts already covered by the project.

## Acceptance

1. Firefly Lantern plus the Bakery activity plus Beachcombing provide at least three repeatable non-racing activities in the released valley.
2. Bakery is a genuine multi-choice replayable decorating activity, not a renamed one-click quest hook.
3. Beachcombing is a genuine multi-observation replayable activity, not rotating flavour text.
4. Both new activities are usable by touch, have concise instructions, no timer pressure and no punitive fail state.
5. Both persist useful records/progress through existing save authorities with no parallel progression system.
6. Each has at least one first-completion reward and multiple finite collection/Wonderbook outcomes, without repeatable Shimmer farming.
7. Existing Bakery shopping/Maple story, Starlight Beach stories, racing, save restoration and world-state behaviour remain intact.
8. Formatting, lint, type-check, unit tests, production build, static smoke, browser compatibility and full browser playtest pass with the 520 KiB app-entry budget unchanged.

## Implementation order

1. Add a small shared repeatable-activity progress module and content definitions for Bakery/Beach outcomes.
2. Implement pure Bakery activity rules/progress with focused unit tests.
3. Add touch-first Bakery presentation and wire it into the existing Bakery after Maple's story completion.
4. Implement pure Beachcombing rules/progress with focused unit tests.
5. Add touch-first Beachcombing presentation and replace the shallow basket action.
6. Integrate first-completion economy rewards and Wonderbook outcomes.
7. Add focused browser acceptance for both replay loops and return flows.
8. Run the full technical gate and merge before beginning WP15.
