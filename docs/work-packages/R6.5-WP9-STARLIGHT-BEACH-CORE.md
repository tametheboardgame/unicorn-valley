# R6.5-WP9 - Starlight Beach Core Region

## Metadata

- ID: `R6.5-WP9`
- Autonomy: Green implementation with Amber visual acceptance
- Dependencies: `R6.5-WP1`, `R6.5-WP2`
- Dependencies state: complete on `main`
- Delivery: PR required
- Base: `main`; approved R6.5 performance policy PR #131 merged as `0a5c7e70d671da49163e8848bb6d1057a10c3256` and WP5 merged as `84884073581dc26c31f0a20745d8eb1aacd1390b`.
- Validated implementation head: `141a88ad64ab4e49e222bc16393a7df845137620`.

## Goal

Add Starlight Beach as one strongly differentiated full new exploration region before preference-led expansion.

## Scope

- production Starlight Beach world map;
- shoreline and shell cove;
- tide-pool area;
- dunes/sand area;
- secret or sheltered pocket;
- clear collision, navigation, return points and gateway connection;
- beach ambience using the existing production audio approach;
- initial residents/visitors through the reusable R6.5 population system;
- region-specific collectable/discovery family;
- Wonderbook/place integration;
- safe phone/tablet traversal;
- enough first-visit interactions that the Beach does not read as an empty content shell.

## Non-goals

These belong to later packages and must not be pulled forward merely to make WP9 larger:

- the two full beach quest/story threads owned by WP10;
- the complete beachcombing/tide-pool repeatable activity owned by WP10/WP14;
- a Beach race course or Rainbow Cup implementation owned by WP12;
- broad economy/shop changes;
- R7 preference-led expansion;
- production deployment.

## Invariants

- Child-first navigation and readable landmarks.
- Touch/mobile is first-class.
- New content reuses existing save, discovery, population, audio and traversal authority.
- No real-world timers, pressure, adverts, purchases or social systems.
- Main remains releasable.
- The approved R6.5 performance-policy envelope and unchanged entry/runtime gates remain binding.

## Acceptance

### Technical

- Beach scene is registered and can be reached from the existing physical valley without diagnostic-only shortcuts.
- Return travel lands safely and predictably.
- Region checkpoint persists the Beach location.
- Map contains distinct shoreline/shell-cove, tide-pool, dunes and sheltered-pocket landmarks.
- At least two existing supporting residents are placed safely without blocking traversal.
- Region discovery plus multiple Beach-specific discoveries/collectables are registered and persist through the existing discovery service.
- Valley map treats Starlight Beach as a real physical region rather than a future placeholder.
- Focused map/topology/population tests pass.
- Full format, lint, typecheck, unit, build, performance, static smoke and browser CI remain green.

Technical acceptance is satisfied on implementation head `141a88ad64ab4e49e222bc16393a7df845137620`:

- Validate green, including 353/353 unit tests;
- application entry approximately 458.7 KiB raw against the unchanged 520 KiB gate;
- browser compatibility green across Chromium, Firefox, WebKit, tablet and mobile projects;
- full Chromium browser playtest green;
- AI project-contract validation green.

### Human/visual

Amber final gate, still pending:

- Starlight Beach is visually unmistakable from existing regions.
- Main paths, water edge, dunes and interactive pockets are readable on the target phone/tablet form factor.
- The first visit feels like a real place rather than a bare future-content shell.

Technical completion does not release this visual gate automatically. The package is therefore `waiting_human` and PR #132 must remain unmerged until this gate is explicitly accepted.
