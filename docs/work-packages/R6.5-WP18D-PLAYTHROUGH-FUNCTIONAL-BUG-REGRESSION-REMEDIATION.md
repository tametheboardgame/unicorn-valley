# R6.5-WP18D - Playthrough Functional Bug and Regression Remediation

## Objective

Resolve the concrete functional defects found during the WP17 human playthrough after the major freeze and tablet-shell foundations are addressed. Reproduce the actual human failure mode first, then fix the underlying defect and add a durable regression where practical.

## Mandatory defect set

### Echo interaction

- Echo currently cannot be spoken to.
- Neither direct tap nor contextual action succeeds.
- Establish the failed interaction path, fix it, and verify both supported interaction routes reach the same dialogue/action authority.

### Moonflower Cottage collision

- Player can walk up/through the back-wall area.
- Correct collision/walkable geometry without breaking intended furniture/doorway movement.

### Cottage decoration state

Investigate the decoration system holistically rather than treating the observations as isolated labels.

Observed:

- placed decoration can appear to remain available in the bag;
- empty/clear selection does not reliably clear the slot;
- ownership, placement and removal state is unclear/inconsistent.

Define and test authoritative rules for owned quantity, placed state, replacing an item and clearing a slot while preserving saves.

### Maple discoverability/progression

The child repeatedly searched for Maple and could not find her while actively trying to complete missions/unlock content.

Do not assume the fix is "add a marker". Determine whether the cause is:

- invalid/hidden progression state;
- NPC scheduling/presence state;
- unclear quest direction;
- world navigation/signposting;
- interaction failure;
- or another defect.

Fix the root cause while preserving exploration.

### Purchase feedback

- Bakery purchase success was not obvious.
- Player repeatedly bought croissants because she could not tell whether the first purchase had succeeded.
- Make transaction success, currency change and acquired item feedback unambiguous.

### Reward feedback

The player was not always sure whether an activity/shop-related flow had awarded currency. Reconcile reward feedback so Shimmer/Star Coin changes are legible without excessive pop-ups.

### Point-and-click facing regression

Revalidate the observed rapid forward/backward facing flicker when tap/click movement drives the unicorn backwards or around direction changes. Fix if reproducible and test the real movement path.

### Placeholder/icon-over-character regressions

Human evidence found unicorns represented by circles/symbols or icon markers in places where a full unicorn representation was expected.

Any remaining instance must be inventoried and classified as:

- intentional map/UI icon;
- temporary technical placeholder that must be removed;
- or incorrect character/world representation.

Do not allow stale automated evidence to close a defect that remains visible in real play.

## Additional defects discovered during remediation

Fix newly discovered defects when they are direct root causes or regressions of the mandatory set and remain bounded. If a discovery expands into a separate system redesign, document it for the correct later WP rather than allowing WP18D to become unbounded.

## Regression-test standard

Where practical, each fixed defect should have a test representing the user-visible failure rather than only a low-level unit test.

Examples:

- enter the real scene and activate Echo;
- move player against the cottage back boundary;
- place/remove decoration and inspect persisted authority;
- traverse Maple's actual quest state;
- buy an item and assert visible confirmation plus state change;
- drive tap-to-move through direction reversals and inspect authoritative facing.

## Acceptance

WP18D is complete when all mandatory defects are either fixed with evidence or explicitly shown not to reproduce because an earlier root-cause fix removed them, with regression coverage added where practical and no new progression blocker introduced.

Move to `R6.5-WP18E - Bag, Map, Creator and Modal Tablet UX`.
