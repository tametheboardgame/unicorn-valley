## H6.9B mandatory integration boundary

1. Use **one** `crystalarium` ID, one `SceneManifest`-owned gameplay scene, canonical `MiniGameLauncher` / `MiniGameSession` and existing `MiniGameOutcomeGateway`. Never author a second world-only gameplay scene or a separate Just Games copy.
2. A new *mergeable* World-first mini-game package must include its **minimal playable Just Games entry in the same package**, including one valid visible variant, sandbox outcome checks, and return navigation. The original H6.9D plan delaying first catalogue registration would violate MG-WP4, so H6.9B must register the shared family and scene atomically. Keep `opening-melody` hidden from Just Games; `resonance-patterns` can be a clearly introductory playable practice mode initially and expand in H6.9C. H6.9D is polish/final cross-context acceptance, not first registration.
3. Require `session !== null`, `source === 'world'`, `sideEffectPolicy === 'world'`, the correct game/variant and authored interaction/location, and confirmed success **before** the world-only unlock adapter grants the Grotto flag/discovery. The shared gateway intentionally accepts a null session for legacy callers; this is **not** sufficient validation for a *new* story unlock.
4. Preserve legacy Grotto open/completed saves, original low/bright/bell quest indices and earned rewards. Just Games replay must never set the entrance flag, change quest state or grant items. Add targeted migration, reload, retry and world/Just Games round-trip tests before visual acceptance.
5. Coordinate registry edits with any independent MG branch before merging. As of this check, draft [MG-WP7 PR #289](https://github.com/tametheboardgame/unicorn-valley/pull/289) also edits `MiniGameCatalogue.ts` and its test; **H6.9B's future branch must check current merged `main` and open PR overlap again immediately before implementation and final merge**. This is an integration conflict risk, not an H6.8 platform-readiness failure.

## Evidence limits and downstream gates

This verification is a review of live merged repository source, established automated contract coverage and the completed **existing** post-merge CI run. No separate local unit/browser command or new gameplay test was executed solely for this documentation checkpoint. H6.9A remains **rules-only**, with no playable door, scene or catalogue registration. Passing H6.8 does not itself approve H6.9B save mutation, gameplay UI, illustrations, accessibility or later H6.9C/D expansion; those retain their own tests and human visual/acceptance gates.

`PROJECT_STATE.json` and `STATUS.md` are shared integration summaries. They are not edited in this World-local checkpoint because open draft PR #176 also owns those root files.
