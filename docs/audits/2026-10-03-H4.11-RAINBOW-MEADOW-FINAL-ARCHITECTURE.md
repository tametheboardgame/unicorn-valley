# R6.5-WP19H4.11 — Rainbow Meadow final architecture audit

Date: 3 October 2026

## Purpose

H4.11 closes Rainbow Meadow after the approved H4.10 visual/gameplay pass. The objective is not another redesign. It is to leave the region with the same ownership discipline used by the rebuilt Moonflower Glade and Sunbeam Village: canonical layout data, area-owned static presentation, specialised stateful managers only where they genuinely add behaviour, and no compatibility-era manager repainting or hiding older Meadow generations after scene creation.

## Final ownership model

| Concern | Final owner | Notes |
| --- | --- | --- |
| Canonical coordinates, districts, gateways, paths, collisions, discoveries and activity anchors | `RainbowMeadowMap.ts` / `RAINBOW_MEADOW_LAYOUT` | Single source of truth for Meadow geometry. |
| Scene lifecycle, player, collision group, discoveries, base environment and region transitions | `RainbowMeadowScene.ts` | Sunbeam Village and Rainbow Run walk-through routing is scene-owned. |
| Canonical path network and west threshold presentation | `RainbowMeadowTraversalPresentation.ts` | Consumes `RAINBOW_MEADOW_LAYOUT`; no global post-step decoration. |
| Boundary hedge/fence/rock presentation | `RainbowMeadowBoundaryPresentation.ts` | Consumes canonical boundary data. |
| Rainbow Disc world presentation | `RainbowDiscMeadowPresentation.ts` | Activity-specific presentation remains isolated. |
| Picnic Hill landscape / story presence | `MarigoldPicnicPresentation` + authoritative presence services | No duplicate core-character ownership. |
| Windmill, flower-circle, petal, butterfly and pond interaction state | `MeadowDepthWorldManager.ts` | Retained as the Meadow equivalent of the current Glade depth/story manager. It owns stateful feature behaviour, not the region layout. |
| Crystal Brook threshold landscape/effects | `R6RegionGatewayArtManager.ts` | Retained shared cross-region presentation. It consumes canonical Meadow/Brook positions rather than maintaining competing Meadow coordinates. |
| Resident routines | population content / ambient population manager | Placements consume the rebuilt Meadow geometry. |
| Lily Pad Leap / Rainbow Disc activities | dedicated activity scene + lazy registration | Sub-screens remain isolated from region composition. |

## Compatibility-era Meadow ownership removed

### `WorldTraversalPolishManager`

Before H4.11 it still:

- painted Rainbow Meadow's complete path network after scene creation;
- added a second west-gateway/threshold presentation;
- owned automatic Sunbeam Village and Rainbow Run transitions;
- carried legacy Meadow label-hiding logic.

H4.11 moves the accepted path/threshold presentation into `RainbowMeadowTraversalPresentation.ts` and moves walk-through routing into the Rainbow Meadow scene through the testable `RainbowMeadowTraversal.ts` resolver. The manager now supports Moonflower Glade only.

### `EnvironmentProductionPresentationManager`

Before H4.11 it still had a Rainbow Meadow branch containing:

- a compatibility background layer;
- the old simple production flower circles;
- a production leaf cluster;
- generic ambient motes.

Those objects were remnants of the pre-H4 layered presentation system. H4.10 already replaced the relevant Meadow dressing with authored wildflower/boundary presentation. H4.11 removes the Meadow environment id, scene registration and production function, and deletes the retired production decoration coordinates from `RAINBOW_MEADOW_LAYOUT`.

### `VisualTighteningManager`

Before H4.11 it still added a second set of pond ripples/reeds on top of the rebuilt scene-owned Rainbow Pond. H4.11 removes Rainbow Meadow from the manager entirely. The manager is now race-only.

## Architecture rules after H4.11

1. **Do not add Rainbow Meadow presentation to a generic global post-step manager.** Static region presentation belongs to the scene or a Meadow-specific presentation module called by the scene.
2. **Do not add duplicate Meadow coordinates outside `RAINBOW_MEADOW_LAYOUT`.** Shared systems may consume canonical coordinates but must not become a second source of truth.
3. **Do not hide obsolete Meadow objects at runtime when the producer can be removed.** H4.11 explicitly removes the remaining compatibility producers instead.
4. **Stateful cross-cutting systems are allowed only when they own behaviour, not composition.** Examples include atmospheric weather, population, story state and shared Crystal Brook threshold effects.
5. **Walk-through and interaction routing must converge on the same destination semantics.** The pure traversal resolver is regression-tested independently from Phaser presentation.
6. **Activity scenes remain isolated.** Rainbow Disc and Lily Pad Leap may be launched from Meadow but do not own Meadow geometry or UI overlays.

## Regression protection

H4.11 adds:

- unit coverage for Sunbeam Village and Rainbow Run walk-through resolution;
- browser coverage requiring exactly one canonical Meadow path network;
- browser coverage requiring the scene-owned physical Sunbeam sign/threshold;
- browser assertions that Rainbow Meadow contains no `world-traversal-polish-detail`, no `visual-tightening-detail`, and no `environment-production:rainbow-meadow:*` objects;
- an assertion that the removed legacy `← Sunbeam Village` text cannot reappear.

## Qualification position

H4.11 is intended as the final Rainbow Meadow consolidation slice. Any later change to Rainbow Meadow should be treated as a new bounded feature/fix, not as permission to restore the pre-H4 multi-manager composition chain.

The separate Rainbow Run Race Hub maturity work remains a post-H4 work package.
