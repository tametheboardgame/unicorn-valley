# R6.5-WP19H6.0 - Crystal Brook requirements, baseline and ownership audit

Date: 3 October 2026  
Baseline main commit: `cab55bfbdc98429cfeb324faf11f8509b2dc64c9`  
Roadmap: `docs/work-packages/R6.5-WP19H6-CRYSTAL-BROOK.md`

## Purpose

H6.0 records the accepted pre-rebuild Crystal Brook state before any H6 structural or visual implementation begins.

This checkpoint is deliberately non-destructive. It does not begin H6.1, move Brook geometry, replace presentation, change progression, add mini-games, alter race navigation or modify save semantics.

The baseline exists so later H6 slices can distinguish deliberate replacement from accidental regression and can retire every legacy presentation owner explicitly.

## Approved H6 requirements carried into the baseline

The committed H6 roadmap requires Crystal Brook to become a coherent river valley with:

- one continuous stream running through the region and reading as the upstream source of the Rainbow Meadow waterfall/pool;
- a cave-mouth/waterfall threshold that is continuous with the Meadow-side H4 work;
- hard natural perimeter boundaries, primarily rocks and boulders;
- one canonical layout authority for Brook structural coordinates;
- preservation of existing exploration, collectables, Ripple/Echo story state and discoverable depth;
- later replacement of the direct Crystal Cascade race gate with an in-world route to the race hub;
- later Crystal Merge and crystal checkers-style mini-games, but only through the shared mini-game platform after the H6.8 dependency gate;
- later whole-area composition, navigation, lifecycle, responsive and performance qualification.

H6.0 itself is evidence and ownership mapping only.

## Current structural authority

### `CrystalBrookMap.ts`

`CRYSTAL_BROOK_MAP` is the strongest existing structured authority, but it is not yet a complete layout authority.

It currently owns:

- map bounds and player spawn;
- the Rainbow Meadow entrance at `120,1090`, approach `340,1090`;
- the six-point shallow-stream route;
- stepping stones;
- four collectable placements;
- Ripple/Grotto NPC visit points;
- the Prism Grotto secret route;
- the current collider set.

It does not currently own all visible paths, water bodies, gateway positions, resident routes, story secret positions, depth interactions, background forms, R6 presentation overlays or race return positions. H6.1 must resolve that split without changing preserved behaviour.

## Mini-game platform dependency boundary

The H6 roadmap was written while the shared mini-game runtime was still a dependency assumption. Current `main` has since merged **MG-WP0** at commit `dc24989ebe`.

Present on current main:

- `MiniGameCatalogue`;
- `MiniGameSession`;
- `MiniGameLauncher`;
- `MiniGameOutcomeGateway`;
- manifest-backed mini-game scene references;
- MG-WP0 unit/architecture contracts.

Not yet present on current main:

- a `JustGamesScene`;
- MG-WP1 caller/scene migrations;
- MG-WP2 complete sandbox side-effect isolation for existing games;
- MG-WP3 Just Games launcher UI;
- the full MG-WP4 readiness/qualification required by the H6 roadmap.

Therefore:

- H6.1 through H6.7 remain independent of the mini-game programme and may proceed after the H6.0 human review;
- H6.9 and H6.10 remain blocked by H6.8;
- H6.8 must re-check actual MG-WP0 through MG-WP4 readiness before either new Crystal Brook game starts;
- H6 must extend the shared catalogue/session/launcher architecture, never create a Brook-specific duplicate launcher, return contract or persistence path.

The existing Crystal Cascade remains a variant of the canonical Rainbow Run Racing family. H6.6 is a world-topology change, not a licence to bypass the race/mini-game platform.

## H6.1 hand-off constraints

When H6.1 is approved to start, it must use this audit as a retirement/migration checklist.

It may:

- introduce the canonical Brook layout authority;
- canonicalise structural coordinates and collision ownership;
- define the continuous river route and cave threshold;
- define perimeter and corridor geometry.

It must not silently:

- remove collectables or discoveries;
- reset or rename Ripple/Echo/Grotto flags;
- change quest completion semantics;
- break Echo's purposeful route;
- strand Grotto/Woods/Meadow/race return positions;
- modify the accepted Meadow-side H4 gateway composition;
- start Crystal Merge or crystal checkers;
- remove a legacy presentation layer before its visible responsibility has an intentional replacement.

## H6.0 checkpoint result

H6.0 is complete when the production baseline evidence exists on the branch and this audit has been reviewed.

No H6.1 implementation is included in this checkpoint.
