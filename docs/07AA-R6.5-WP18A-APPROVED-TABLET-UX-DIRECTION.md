# R6.5-WP18A Approved Landscape Tablet UX Direction

Status: Approved by user on 2026-09-05.

This document is the durable implementation authority for the landscape-tablet control and interface direction approved during R6.5-WP18A. The four user-supplied concept images reviewed in the approval chat are the visual reference. Their expensive 3D presentation is illustrative only; **layout, hierarchy, touch placement, readability and interaction design are the authority**.

## Product principle

Unicorn Valley should feel designed for a child holding a landscape tablet. The world remains the main visual surface and controls sit in natural thumb zones without covering important play space.

Reference device: Samsung Galaxy Tab S8, Chrome, landscape.

Desktop keyboard and mouse remain supported as a secondary input path.

## Shared exploration shell

Approved direction:

- compact top navigation containing **Map, Bag, Book and Settings** as clearly illustrated, independently tappable actions;
- compact currency/status counters at the top without creating a large permanent HUD wall;
- current location displayed at the top-right;
- movement control in the **lower-left thumb zone**, using the circular four-direction control shown in the approved concepts;
- contextual primary action in the **lower-right thumb zone**, large and unmistakably tappable, with the label changing to the current action such as **Talk to Pip**;
- **Gallop** as a separate secondary action beside the contextual primary action;
- a small **bottom-centre contextual hint strip**, used for simple child-readable prompts rather than desktop keyboard instructions;
- direct NPC/world tapping and tap-to-move remain first-class alongside the movement control;
- contextual actions appear only when meaningful rather than leaving large inactive controls on screen;
- the world view must remain substantially unobstructed.

The supplied exploration concepts establish the desired proportions and hierarchy: the controls are visually substantial enough for touch, but hug the edges and corners instead of becoming a permanent bottom control bar.

## Race controls

Approved direction:

- dedicated race HUD, not the exploration D-pad or Talk layout;
- **left/right steering buttons in the lower-left thumb zone**;
- **Jump and Gallop in the lower-right thumb zone**;
- controls must stay out of the central track and must not hide upcoming obstacles;
- race position and progress remain compact across the top;
- Pause remains top-right;
- small bottom-centre hint/status strip may be used where useful;
- racing must not depend on a browser long-press gesture;
- Gallop/accelerate behaviour must use safe tap/hold handling that cannot trigger Chrome long-press navigation behaviour;
- multi-touch must permit steering and race actions together without sticky input states.

The user-supplied race concept is the layout authority for control placement and screen occupation.

## Bag and inventory

Approved direction:

- Bag opens as a large, polished landscape modal while the world remains visually contextual behind it where practical;
- top-level navigation remains recognisable and Bag is visibly selected;
- clear category tabs such as **Food, Quest, Decor and Keepsakes**;
- inventory is scrollable and has no six-item ceiling;
- item tiles are large, visual and child-readable, with quantity displayed directly on the item;
- selected item has a dedicated detail panel;
- usable items expose a large explicit action such as **Eat**;
- Bag and Map remain distinct obvious actions rather than hiding Map inside inventory;
- close/back action is visually unmistakable.

The approved concept uses richer illustration than the current production game can necessarily match immediately, but the spatial organisation and interaction hierarchy are required.

## Unicorn Creator

Approved direction:

- large unicorn preview occupies roughly half the landscape screen;
- customisation is organised into progressive categories rather than showing every option simultaneously;
- approved category model: **Main, Colours, Mane & Tail, Horn, Markings, Accessories**;
- only the active category exposes its option grid;
- option choices use large visual cards/swatches suitable for touch;
- naming remains clearly readable and must not be interfered with by gameplay keyboard shortcuts;
- obvious **Back**, **Randomise**, and **Save Unicorn** actions;
- the unicorn preview remains the visual focus rather than being squeezed by controls.

The user-supplied Creator concept is the visual authority for this split-preview layout and progressive category interaction.

## Visual language

Preserve the existing Unicorn Valley storybook identity:

- rounded cards and buttons;
- cream, lavender, purple and gold control language;
- large illustrated icons;
- soft shadows and clear selected states;
- high contrast text sized for a child on a tablet;
- minimal permanent panels over the world.

Do not attempt to reproduce the concept images' expensive 3D art style in production. Implementation should use the existing Phaser/TypeScript game art and UI pipeline while matching the approved **layout and control behaviour**.

## Implementation stop rule

If implementation cannot reasonably match these approved layouts within the existing browser architecture, or if a required technical compromise would materially change control placement, hierarchy or child usability, stop and request user input rather than silently drifting from the concepts.

## Ownership

- WP18B may proceed immediately because the WP18A visual gate is released.
- WP18C must implement the exploration and race layout above.
- WP18E must implement the Bag/Map and Unicorn Creator layout above.
- Later packages may refine visual polish but must not contradict this approved direction without explicit user approval.
