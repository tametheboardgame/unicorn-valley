# R6-WP6.18 - Playthrough Status and Remediation Record

## Purpose

This document records the current R6-WP6.18 human-playthrough gate, the end-to-end playthrough findings, the bounded remediation packages created from those findings, and the exact condition for moving into R7.

It supplements `07F-R6-WP6.11-6.18-PRE-R7-DELIGHT-PHASE.md`. The hard-stop rule in that document remains authoritative.

## Current status

R6-WP6.11 through R6-WP6.17 are complete and merged.

R6-WP6.18 is active and remains a **human target-player hard stop**.

The first human playthrough produced the remediation packages R6-WP6.18A/B through R6-WP6.18F. Follow-up mobile playthrough evidence confirmed that most of those defects were fixed, but exposed three remaining map/presentation issues assigned to R6-WP6.18G and a further mobile race-control usability issue assigned to R6-WP6.18H.

R6-WP6.18G is complete and merged in PR #117. R6-WP6.18H is the active remediation.

R7-WP7.1 and all R7 expansion work remain blocked until further human playthrough evidence is supplied and the user explicitly releases the hard stop.

## First playthrough findings

The first R6-WP6.18 playthrough identified the following issues:

- the Unicorn Creator was too cramped and difficult to read on a portrait mobile display;
- mobile interaction text was too small and `Talk to Pip` did not read clearly as an action;
- prototype circular NPC markers remained visible around production character art;
- point-and-click backwards movement could alternate the unicorn's facing direction every step;
- Sunbeam Village shopfronts still looked like prototype blocks and were not convincing places to enter;
- the Crystal Brook entrance did not read as a natural world route and sat too close to the race route;
- Crystal Brook and Whispering Woods needed stronger authored gateways/environment identity;
- Crystal Cascade felt structurally unwinnable during normal human play.

These findings were treated as defect evidence, not as permission to begin speculative R7 expansion.

### R6-WP6.18E - Crystal Cascade human-winability balance

Merged in PR #113.

The playthrough finding exposed a genuine data defect: the reused NPC mistake tables referenced only Rainbow Run obstacle IDs, so Crystal Cascade NPCs effectively attempted the whole course without their intended mistakes.

The remediation:

- added Crystal Cascade obstacle IDs to the existing Nova, Clover and Breeze mistake data;
- left player speed, race physics, assistance settings and shortcut mechanics unchanged;
- proved through production-system simulation that a clean standard player can win without Prism Current;
- proved a competent one-mistake player still has a first-place route;
- added real-input browser validation requiring first place, zero obstacle hits and zero shortcut use for the clean route.

Prism Current therefore remains an optional advantage rather than a hidden requirement.

### R6-WP6.18F - Prototype NPC marker cleanup

Merged in PR #114.

- removed residual prototype circles/icons beneath production Willow, Marigold and Pebble art;
- preserved NPC names, interaction targeting, story state and collision;
- left deliberate portrait framing untouched;
- added browser regression coverage.

### Shared R6.18 CI gate hardening

Merged in PR #115.

This was test/infrastructure-only work required because slow CI timing was obscuring otherwise valid remediation changes.

No production gameplay behaviour was changed by this package.

## Follow-up playthrough findings

A later mobile playthrough confirmed that a large proportion of the first remediation pass was working as intended. The following remaining defects were recorded:

- Pebble still had a beige circle and rock icon visibly covering the production character;
- the Rainbow Meadow path to the Crystal Brook cave branched too late and crossed directly through the Ribbon Board area;
- old R5 destination sign labels remained visible behind the newer production cave, woodland and race-gate labels;
- mobile race controls still overlaid the race graphics and were too small and awkward for comfortable touch play.

Investigation showed that Pebble's remaining circle was not the original prototype NPC marker covered by WP6.18F. It came from the independent legacy Pebble story presentation, which created a second cover and icon at the same position. The existing WP6.18F regression was therefore valid but incomplete for the final composed scene.

The race-control finding is presentation and touch ergonomics rather than a race-physics defect. The existing held Run, Jump and assistance input model remains authoritative and is reused by the remediation.

## Follow-up remediation packages

### R6-WP6.18G - Final playthrough map clean-up

Merged in PR #117.

This package covers the three remaining map/presentation findings.

Scope:

- suppress the legacy Pebble story cover and rock icon while retaining its talk prompt, interaction zone and story routing;
- replace the D2 Crystal Brook meadow branch with an earlier route that leaves the main path around `(1900, 1040)` and curves south around the Ribbon Board;
- retain the existing Crystal Brook cave position and all transition coordinates;
- hide only the obsolete static R5 destination sign inside each production-upgraded gateway container;
- retain R5 gateway interaction zones, proximity prompts, race locks and transition semantics;
- add unit and browser regression coverage for all three findings.

Detailed scope and acceptance are recorded in `07S-R6-WP6.18G-FINAL-MAP-CLEANUP.md`.

### R6-WP6.18H - Mobile race controls

This package is the active remediation for the newly recorded mobile race-control finding.

Scope:

- move the mobile race controls out of the race graphics;
- cover both the standard race flow and Nova's mandatory first-run tutorial;
- provide large held Run and Jump primary controls plus clear Help and Leave actions;
- place the controls directly below the game view in portrait;
- reserve a dedicated layout row below the resized canvas in landscape so the controls cannot overlap the game view;
- drive the existing Phaser Run, Jump, assistance and exit actions rather than duplicating race logic;
- preserve simultaneous held Run plus Jump input;
- disable the hidden in-canvas touch hit areas while the mobile deck is active;
- preserve desktop keyboard controls, race physics, tuning, rewards and save behaviour;
- add portrait, landscape and tablet touch regressions.

Detailed scope and acceptance are recorded in `07T-R6-WP6.18H-MOBILE-RACE-CONTROLS.md`.

## Remaining human gate

After R6-WP6.18H is merged and deployed, another real playthrough of the current build is required.

The human review should concentrate on:

- whether the repaired mobile creator remains comfortable to use;
- whether actions and prompts are obvious without adult explanation;
- whether mobile race Run and Jump controls are large, comfortable and clearly separated from the race graphics in both portrait and landscape;
- whether holding Run while pressing Jump feels natural on a phone or tablet;
- whether Sunbeam Village, Crystal Brook and Whispering Woods now feel like authored places rather than prototype spaces;
- whether the Crystal Brook meadow route now reads naturally and avoids the Ribbon Board cleanly;
- whether Pebble and all other production NPCs are free from leftover placeholder presentation;
- whether gateway names appear once, cleanly, without old labels underneath;
- whether Crystal Cascade feels fair and winnable in ordinary play;
- whether any progression, save, interaction, movement, race or return-path defect appears during normal play;
- what the target player repeatedly chooses to do for enjoyment;
- what characters, locations, activities or customisation options are requested spontaneously;
- where boredom, confusion, frustration or delight appears without prompting.

New defects found during that playthrough may continue to be fixed as bounded R6-WP6.18 remediation packages.

## R7 release condition

Do not begin R7-WP7.1 until all of the following are true:

- enough of the repaired build has been played to provide meaningful preference evidence;
- any newly discovered blocker has either been fixed or has an explicit accepted disposition;
- the playthrough provides useful evidence about what should receive deeper expansion;
- the user explicitly releases the R6-WP6.18 hard stop.

Until then, the correct project state is **R6-WP6.18 - active remediation and awaiting further human playthrough feedback**.
