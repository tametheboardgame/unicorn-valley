# R6-WP6.18 - Playthrough Status and Remediation Record

## Purpose

This document records the current R6-WP6.18 human-playthrough gate, the first end-to-end playthrough findings, the bounded remediation packages completed from those findings, and the exact condition for moving into R7.

It supplements `07F-R6-WP6.11-6.18-PRE-R7-DELIGHT-PHASE.md`. The hard-stop rule in that document remains authoritative.

## Current status

R6-WP6.11 through R6-WP6.17 are complete and merged.

R6-WP6.18 is active and remains a **human target-player hard stop**.

The first human playthrough pass produced a concrete remediation list. All currently recorded defects from that pass have now been addressed in bounded R6-WP6.18 packages and merged to `main`.

R7-WP7.1 and all R7 expansion work remain blocked until further human playthrough evidence is supplied and the user explicitly releases the hard stop.

## First playthrough findings

The first R6-WP6.18 playthrough identified the following issues:

- the Unicorn Creator was too cramped and difficult to read on a portrait mobile display;
- mobile interaction text was too small and `Talk to Pip` did not read clearly as an action;
- prototype circular NPC markers remained visible around production character art;
- point-and-click backwards movement could alternate the unicorn's facing direction every step;
- Sunbeam Village shopfronts still looked like prototype blocks and were not convincing places to enter;
- the Crystal Brook entrance did not read as a natural world route and sat too close to the race route;
- Crystal Brook and Whispering Woods needed stronger authored gateways/environment identity;
- Crystal Cascade felt structurally unwinnable during normal human play.

These findings were treated as defect evidence, not as permission to begin speculative R7 expansion.

## Completed remediation packages

### R6-WP6.18A/B - Mobile creator and action clarity

Merged in PR #109.

- added grouped portrait creator controls beneath the canvas;
- improved mobile creator readability and touch usability;
- added explicit child-readable interaction actions, including `Talk to Pip`;
- improved compact-landscape interaction prompt legibility;
- added mobile touch regression coverage.

### R6-WP6.18C - Click-navigation facing stability

Merged in PR #110.

- fixed alternating facing during backwards point-and-click travel;
- synchronised click-navigation facing with the authoritative player entity;
- preserved keyboard handoff and existing movement/collision behaviour;
- added unit and browser regressions.

### R6-WP6.18D1 - Sunbeam Village shops and interiors

Merged in PR #111.

- replaced the three generic prototype shop facades with authored storefronts;
- made Sunbeam Bakery, Twinkle & Thread and Story House enterable;
- added distinct interiors;
- routed Twinkle & Thread into the existing real shop/economy flow rather than duplicating it;
- preserved return position and existing progression/economy contracts.

### R6-WP6.18D2 - Region gateways and environment art

Merged in PR #112.

- gave Rainbow Meadow a separate authored path to a Crystal Brook cave entrance;
- visually separated Crystal Brook travel from the race hub route;
- added a stronger Crystal Brook to Whispering Woods trail/threshold;
- replaced portal-like race access with a dedicated crystal race path/gate;
- strengthened Crystal Brook and Whispering Woods environment identity;
- preserved established traversal coordinates, save state and race semantics.

### R6-WP6.18E - Crystal Cascade human-winability balance

Merged in PR #113.

The playthrough finding exposed a genuine data defect: the reused NPC mistake tables referenced only Rainbow Run obstacle IDs, so Crystal Cascade NPCs effectively attempted the whole course without their intended mistakes.

The remediation:

- added Crystal Cascade obstacle IDs to the existing Nova, Clover and Breeze mistake data;
- left player speed, race physics, assistance settings and shortcut mechanics unchanged;
- proved through production-system simulation that a clean standard player can win without Prism Current;
- proved a competent one-mistake player still has a first-place route;
- added real-input browser validation requiring first place, zero obstacle hits and zero shortcut use for the clean route.

Prism Current therefore remains an optional advantage rather than a hidden requirement.

### R6-WP6.18F - Prototype NPC marker cleanup

Merged in PR #114.

- removed residual prototype circles/icons beneath production Willow, Marigold and Pebble art;
- preserved NPC names, interaction targeting, story state and collision;
- left deliberate portrait framing untouched;
- added browser regression coverage.

### Shared R6.18 CI gate hardening

Merged in PR #115.

This was test/infrastructure-only work required because slow CI timing was obscuring otherwise valid remediation changes.

- replaced synthetic mobile clicks with real touch/tap gestures where appropriate;
- separated transition hitch limits from settled frame-performance measurements;
- replaced fragile fixed-duration movement/race waits with bounded state-based waits;
- gave the complete Chromium suite a realistic CI job budget without weakening individual acceptance thresholds.

No production gameplay behaviour was changed by this package.

## Remaining human gate

The next required work is another real playthrough of the current deployed build.

The human review should concentrate on:

- whether the repaired mobile creator is now genuinely comfortable to use;
- whether actions and prompts are obvious without adult explanation;
- whether Sunbeam Village, Crystal Brook and Whispering Woods now feel like authored places rather than prototype spaces;
- whether Crystal Cascade feels fair and winnable in ordinary play;
- whether any remaining prototype visual residue is visible;
- whether any progression, save, interaction, movement, race or return-path defect appears during normal play;
- what the target player repeatedly chooses to do for enjoyment;
- what characters, locations, activities or customisation options are requested spontaneously;
- where boredom, confusion, frustration or delight appears without prompting.

New defects found during that playthrough may continue to be fixed as bounded R6-WP6.18 remediation packages.

## R7 release condition

Do not begin R7-WP7.1 until all of the following are true:

- enough of the repaired build has been played to provide meaningful preference evidence;
- any newly discovered blocker has either been fixed or has an explicit accepted disposition;
- the playthrough provides useful evidence about what should receive deeper expansion;
- the user explicitly releases the R6-WP6.18 hard stop.

Until then, the correct project state is **R6-WP6.18 - awaiting further human playthrough feedback**.
