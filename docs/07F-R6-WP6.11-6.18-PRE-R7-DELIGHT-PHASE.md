# R6-WP6.11 to R6-WP6.18 - Pre-R7 Delight and Personalisation Phase

## Purpose

This phase extends R6 after the mobile portrait remediation and before R7 daughter-led expansion.

The objective is to use the waiting period before the next full target-player playthrough on high-value presentation, personalisation and resilience work that is deliberately low-risk to later gameplay direction.

This phase must make the game feel more finished without pre-empting the evidence that R7 is supposed to obtain from real play behaviour.

## Locked scope boundary

The following are in scope:

- front-end presentation;
- title/menu art and interaction polish;
- settings and save/profile UX;
- additive unicorn customisation;
- accessibility and input UX;
- dialogue/UI presentation;
- ambient art, micro-animation and audio polish;
- loading/error/recovery presentation;
- reusable cosmetic/content-authoring foundations.

The following are explicitly out of scope until the hard playtest stop is cleared:

- core progression redesign;
- new quest structure or major story branches;
- economy/currency redesign;
- racing balance or core race mechanics;
- movement model changes beyond presentation/input defects;
- world topology, map structure or collision redesign;
- major new activities or gameplay systems;
- changes whose value depends on guessing what the target player will prefer;
- destructive save changes.

Prefer additive, data-driven changes. Avoid a save-schema bump unless there is no reasonable alternative. Existing saves must remain valid throughout the phase.

## R6-WP6.11 - Main Menu Deluxe and Title Experience

Dependencies: R6-WP6.10

Goal:

- replace the functional title/front door with a polished, child-facing home screen that immediately feels like a finished game.

Deliverables:

- bespoke Unicorn Valley title/home artwork suitable for production use;
- polished main-menu composition using the established production UI language;
- Continue action shown and prioritised only when a valid save exists;
- New Game action with safe overwrite confirmation when progress already exists;
- Settings entry;
- My Unicorn / Redesign Unicorn entry when a valid unicorn exists;
- clear loading/disabled states;
- subtle, reduced-motion-aware ambient animation such as sparkle, cloud, foliage or parallax treatment;
- compact version/build information outside the primary child-facing hierarchy;
- responsive desktop/tablet/phone layout verification.

Acceptance:

- a returning player can reach the existing save in one obvious action;
- a new player can begin without seeing irrelevant controls;
- destructive start-over behaviour remains protected;
- all existing gameplay routing remains unchanged behind the new presentation;
- reduced-motion preference removes or simplifies decorative motion;
- production and mobile browser smoke checks remain green.

## R6-WP6.12 - Save, Profile and Redesign Unicorn UX

Dependencies: R6-WP6.11, R6-WP6.8

Goal:

- make the existing single-player save feel understandable and personal without introducing a risky new save architecture.

Deliverables:

- clear single-profile presentation for the current unicorn;
- My Unicorn entry from the main menu;
- safe route to reopen appearance customisation for an existing save;
- optional rename route if it can use the existing profile field safely;
- explicit save/return behaviour from redesign flow;
- Cancel / return without unintended changes;
- New Game overwrite warning that distinguishes starting over from editing the current unicorn;
- recovery-safe handling if profile or appearance data is missing/corrupt;
- no fake multi-slot implementation unless a later roadmap explicitly commits to real multi-save support.

Acceptance:

- existing progress survives appearance changes;
- redesigning the unicorn cannot reset quests, inventory, friendships, races, discoveries or home state;
- cancelling redesign restores the prior appearance;
- corrupt/missing cosmetic values fall back safely rather than blocking Continue;
- no destructive action occurs on a single accidental tap/click.

## R6-WP6.13 - Unicorn Creator Plus

Dependencies: R6-WP6.1, R6-WP6.12

Goal:

- turn the creator into a richer play experience and stronger expression tool while preserving the existing modular player renderer and save compatibility.

Deliverables:

- substantial creator layout/composition polish;
- larger, better-framed live unicorn preview;
- clearer category navigation and selected-state feedback;
- additional body colours where the production palette supports them;
- additional mane styles and colours;
- additional tail styles and colours;
- additional horn styles;
- additional eye colours/styles where technically compatible;
- additional markings such as stars, hearts, freckles/blush or equivalent child-friendly motifs;
- expanded accessory choices such as bows, flowers, ribbons, crowns or scarves where the existing renderer can support them cleanly;
- improved Randomise behaviour using all compatible categories;
- Reset / sensible default behaviour;
- name-entry UX review so game control keys never interfere with text input;
- keyboard, touch and pointer creator navigation;
- data-driven registration so future cosmetic additions do not require bespoke scene code.

Acceptance:

- all new combinations render without clipping or invalid layer ordering at creator and gameplay scale;
- existing saved cosmetic IDs still render correctly;
- new choices are additive and do not alter progression or reward balance;
- name entry accepts ordinary letters regardless of gameplay key bindings;
- creator remains usable on target tablet/phone layouts;
- randomisation cannot generate invalid combinations.

## R6-WP6.18 - Full Playthrough Hard Stop and Pre-R7 Review

Dependencies: R6-WP6.11 through R6-WP6.17 complete and deployed

Status: **Hard stop requiring human target-player feedback**

Goal:

- stop autonomous feature expansion and obtain a proper end-to-end playthrough before R7 commits to any daughter-led expansion branch.

Required automated gate before handoff:

- formatting/lint/typecheck/unit tests green;
- production build and static smoke green;
- full Chromium gameplay regression green;
- Chromium/Firefox/WebKit compatibility matrix green;
- representative desktop/tablet/phone visual checks complete;
- Cloudflare preview green on the exact final head;
- merged `main` production deployment successful;
- no known progression blocker or startup/continue blocker.

Human playthrough checklist:

- first impression of the new title/home screen;
- New Game flow;
- unicorn creation and naming;
- creator options and ease of use;
- Continue flow;
- My Unicorn / Redesign Unicorn flow;
- settings discoverability and usefulness;
- touch/keyboard usability as relevant;
- complete existing story/exploration/racing/home loop where practical;
- points of confusion, boredom, frustration or delight;
- features repeatedly revisited without prompting;
- characters/places/activities requested spontaneously;
- visual or audio presentation issues missed by automation.

Hard-stop rule:

- do not begin R7-WP7.1 Structured Preference Review or any R7-WP7.2 expansion branch until the user has completed enough of this playthrough to provide meaningful feedback and explicitly releases the hard stop;
- defects found during the playthrough may be handled as bounded R6-WP6.18 remediation sub-packages before the hard stop is considered cleared;
- if the playthrough exposes a major architectural or progression problem, prioritise diagnosis/recovery over cosmetic expansion.

Acceptance:

- playthrough feedback is recorded in the repository;
- blocking defects have a resolution or explicit remediation package;
- observed preferences are sufficient to begin R7-WP7.1 without guessing;
- user explicitly approves moving beyond the hard stop.
