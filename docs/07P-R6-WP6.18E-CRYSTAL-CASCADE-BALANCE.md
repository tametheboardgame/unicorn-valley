# R6-WP6.18E — Crystal Cascade human-winability and balance validation

## Purpose

This bounded R6-WP6.18 remediation addresses the human playthrough finding that Crystal Cascade felt structurally unwinnable on standard assistance.

The review confirmed a real data defect rather than simply a difficult course: Crystal Cascade reused the Rainbow Run NPC definitions, but every configured NPC mistake referenced Rainbow Run obstacle IDs. Crystal Cascade therefore gave the NPC field no intentional mistakes at all, while Breeze could run above the player's standard base pace.

The wider R6-WP6.18 human-feedback hard stop remains active. This package does not release R7.

## Balance change

The existing three NPC identities, paces and variance remain unchanged. Their mistake tables now include Crystal Cascade obstacle IDs as well as their established Rainbow Run mistakes:

- **Nova** can mistime the first reed hurdle;
- **Clover** can mistime the second driftwood log;
- **Breeze** can mistime the first driftwood log and final reed hurdle.

Because `mistakeObstacleIds` are course-feature IDs, the added Cascade IDs have no effect in Sunrise Sprint / Rainbow Run. This preserves the existing race while giving Crystal Cascade its intended human variance.

## Standard-player target

Automated race simulation using the production movement, jump, boost, obstacle and NPC systems now verifies that:

- a clean standard player can finish first without using Prism Current;
- a competent standard player who makes one obstacle mistake still has a realistic first-place route;
- every NPC encounters at least one intentional Crystal Cascade mistake;
- Prism Current remains beneficial but is no longer required to overcome structurally perfect NPC racing.

The clean standard simulation currently finishes at approximately 9.3 seconds, with the tuned NPC field following behind. This is a validation target rather than a new hard-coded finish time in gameplay.

## Real-input browser validation

`tests/play/r6-wp6.18e-crystal-cascade-balance.spec.ts` selects the real Crystal Cascade course through the diagnostics API, starts the production `RaceScene`, and sends ordinary SPACE jump input ahead of the four course obstacles.

The browser regression verifies:

1. the race finishes through normal runtime input;
2. the player finishes first;
3. Prism Current was not used;
4. the actual finish panel reports first place.

No result record is injected to manufacture a win.

## Shortcut clarity

Crystal Cascade already has a visible in-course Prism Current presentation that identifies the glowing stream and instructs the player to jump into it. With the NPC correction above, this reads as an optional skill/reward route rather than an undocumented requirement for victory.

## Boundary

This package does not change:

- player base speed;
- standard or extra-help assistance multipliers;
- race physics;
- Crystal Cascade obstacle geometry;
- Prism Current geometry or progress skip;
- reward/economy values;
- save schema or race unlock progression;
- the R6-WP6.18 hard-stop status.

## Exit condition

E is complete when formatting, lint, TypeScript, unit tests, production build/performance budgets and browser playthrough gates are green and the change is merged to `main`. The project must then remain at R6-WP6.18 until the user explicitly signs off the human playthrough hard stop.
