# R6-WP6.18I/J - Final Crystal Cascade Gate and Path Fixes

## Trigger

A further real mobile playthrough after R6-WP6.18H confirmed that the general mobile experience was substantially improved, but exposed two final blockers before the R6 hard stop can be released:

- the Crystal Cascade race entrance displayed its interaction prompt but could not be reliably entered by touch;
- the newer gateway paths read as differently coloured overlays laid over the underlying world paths rather than as natural continuations of each region's path network.

These are bounded R6-WP6.18 remediation defects. They do not begin R7.

## R6-WP6.18I - Crystal Cascade touch entry

The existing R5 Crystal Cascade gateway remains authoritative for unlock checks, save checkpointing, active race-course selection and the transition into `RaceScene`.

The defect was in presentation/input reachability: mobile users were asked to tap the race gate, but the only pointer target was the legacy 170 x 230 Phaser zone inside the old gateway container. At phone scale this was unnecessarily small and easy to miss.

The remediation adds a larger temporary transparent touch surface while the player is close to the Crystal Cascade gate. That surface:

- exists only while the player is within the gate approach area;
- uses a 360 x 360 touch target centred over the authored race gate;
- relays the pointer action to the existing R5 functional gateway zone;
- therefore preserves the existing unlock, save, race-selection and scene-transition behaviour rather than duplicating it;
- disappears when the player moves away so normal point-and-click world movement is not obstructed.

## R6-WP6.18J - Gateway path visual integration

The R6 production gateway art originally drew its connector paths at a high presentation depth and with gateway-specific colours. During real mobile play this made them read as separate coloured strips laid on top of the maps.

The remediation keeps the authored routes and gateway destinations, but changes their visual contract:

- the Rainbow Meadow to Crystal Brook branch uses Rainbow Meadow's existing path widths and cream/gold palette;
- the Crystal Brook to Whispering Woods branch uses Crystal Brook's existing path widths and palette;
- the Crystal Brook to Crystal Cascade branch uses the same Crystal Brook path treatment;
- replacement path graphics sit alongside the native ground-path layer rather than at the high gateway-art depth;
- the older differently coloured R6 path graphics remain present for compatibility but are hidden;
- gateway structures, collisions, coordinates, transitions and race logic are unchanged.

## Regression coverage

Browser coverage verifies that:

- the older coloured R6 gateway path graphics are hidden;
- the corrected Meadow branch and both Crystal Brook branches are visible at the native path layer;
- on a real touch-capable 412 x 915 viewport, the player can approach Crystal Cascade, the enlarged gate target becomes interactive, and a touchscreen tap enters the actual Crystal Cascade `RaceScene` through the existing gateway logic.

## Acceptance

R6-WP6.18I/J is complete when validation, browser compatibility and full automated playthrough gates are green, the branch is deployed and reviewed, and the merged production build is available for a short final human confirmation.

The confirmation should verify only the two reported defects: Crystal Cascade can be entered naturally by touch, and the affected Meadow/Crystal Brook paths visually belong to their surrounding path networks.

R7 remains blocked until that human confirmation is clean enough and the user explicitly releases the R6-WP6.18 hard stop.
