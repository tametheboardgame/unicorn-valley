# R6-WP6.10 Mobile Portrait Playability Remediation

## Trigger

A real Android portrait playtest immediately after R6 closeout exposed a practical mobile blocker that the automated browser/deployment gate had not captured well enough.

The 16:9 game canvas was vertically centred inside a tall phone viewport, leaving a large empty band above and below it. The existing exploration movement pad was rendered inside the scaled Phaser canvas, so its already-small controls became very small physical touch targets. Gallop was present only as a small in-canvas action and was not obvious or comfortable to use.

Inspection also found a functional issue in the shared exploration shell: Moonflower Glade could receive a shell-created touch pad backed by a fallback `PointerTouchInputAdapter` rather than the scene's actual movement adapter. A visible pad could therefore be disconnected from player movement.

## Scope

This is a bounded post-closeout R6 remediation so mobile playtesting can happen before the pre-R7 polish phase and later R7-WP7.1 Structured Preference Review.

It changes presentation and pointer/touch input only. It does not change save schema, quests, story, progression, world collision, navigation or content.

## Implementation

- Narrow portrait touch viewports pin the 16:9 Phaser canvas to the top of the usable browser viewport instead of vertically centring it.
- The otherwise-unused lower portrait area contains a dedicated fixed DOM touch-control layer rather than shrinking movement controls inside the game canvas.
- Direction controls have thumb-sized targets with a minimum 54 px footprint.
- Gallop is a separate, clearly labelled action with a minimum 88 px footprint.
- `viewport-fit=cover`, dynamic viewport height and safe-area insets are used so controls remain clear of modern phone browser/system UI.
- Pointer hold/release semantics feed the existing `PointerTouchInputAdapter`; keyboard and non-portrait control paths remain unchanged.
- `ExplorationShellWorldManager` now reuses a scene's own pointer adapter when one exists, so Moonflower Glade's shared-shell touch controls drive the same input source as player movement.
- Fixed portrait controls release input and hide while the owning world scene is paused, then restore on resume. Book, Bag and other pause-driven overlays therefore remain unobstructed.
- Landscape phones, tablets and desktop browsers retain the existing in-canvas layout.

## Automated verification

The compatibility suite includes a dedicated 390×844 phone regression on both configured Chromium and WebKit mobile-touch projects. The test:

- loads Moonflower Glade from the production build;
- requires the canvas to begin at the top of the viewport;
- requires all four movement buttons to be visible and at least 54×54 px;
- requires the Gallop control to be visible, explicitly labelled and at least 88×88 px;
- holds the right movement control and verifies through browser diagnostics that the actual player unicorn moves.

Existing gates remain mandatory:

- formatting, lint, TypeScript, unit tests, production build, performance budget and static smoke;
- complete Chromium browser regression;
- Chromium/Firefox/WebKit compatibility matrix;
- exact-head Cloudflare Pages preview;
- successful post-merge `main` CI and production deployment.
