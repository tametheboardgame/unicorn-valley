# R6-WP6.18H - Mobile Race Controls

## Trigger

A follow-up mobile playthrough identified that the race controls still sat over the race graphics and remained too small and awkward for comfortable touch play.

R6 remains at the mandatory WP6.18 human-feedback hard stop. This package is a bounded usability remediation and does not release R7.

## Problem

The race scenes' original touch presentation was authored directly inside the fixed 1280x720 Phaser canvas:

- the Jump control occupied the lower-right race view;
- race assistance occupied the upper-right race view;
- the exit action occupied the upper-left race view;
- scaling the complete canvas down on a phone made these controls physically small even though their game-space dimensions were reasonable;
- the controls obscured scenery and race information because they shared the play surface;
- the same presentation was used by both the standard race scene and the mandatory Nova first-run tutorial, so a new mobile player encountered the problem before reaching the normal race flow.

The race input model itself was not defective. Keyboard input, race physics, automatic forward movement, Jump semantics and assistance settings already behaved correctly.

## Implementation

WP6.18H adds a touch-only DOM race-control deck that reuses the existing Phaser controls as the authoritative input path in both `RaceScene` and `NovaTutorialRaceScene`.

On coarse-pointer devices:

- the original in-canvas Jump, race-help and exit presentation is hidden and its touch hit areas are disabled;
- a large `JUMP` button is presented outside the game canvas;
- the existing race-help mode is mirrored as a large touch button and continues to use the existing settings store;
- the existing leave-race action is mirrored as a large touch button;
- portrait layout places the control deck directly below the 16:9 game view;
- landscape layout reserves a dedicated bottom control bar and shrinks the game view to remain above it;
- safe-area insets are respected.

The DOM controls do not implement a parallel race model. They drive the existing Phaser objects and `PointerTouchInputAdapter`, preserving the established race input and progression behaviour.

## Desktop and keyboard boundary

On fine-pointer desktop layouts the new control deck is not loaded or displayed. Existing keyboard controls and the original in-canvas desktop presentation remain authoritative.

This package does not change:

- race speed or physics;
- obstacle timing or hitboxes;
- NPC racing behaviour;
- automatic forward movement;
- race rewards or progression;
- assistance-mode tuning;
- save schema;
- course layouts.

## Regression coverage

Browser coverage verifies that:

- portrait touch controls appear below the canvas rather than over it;
- landscape touch controls occupy a dedicated bar below the resized canvas;
- Help and Leave targets are at least 64px high in portrait;
- the primary Jump target is substantially larger than the secondary actions;
- landscape touch targets remain at least 74px high;
- the original in-canvas race controls are hidden and cannot intercept touch while the mobile deck is active;
- the mobile Help button changes the real race assistance setting;
- the mobile Jump button drives a real race jump through the existing input path;
- the mobile Leave button returns through the existing race exit path;
- the same outside-canvas control contract works in the mandatory Nova first-run tutorial as well as the standard race scene.

## Acceptance

R6-WP6.18H is complete when validation and browser regressions are green and a deployed mobile build presents race controls outside the race graphics with comfortably large touch targets in portrait and landscape, including the Nova first-run tutorial.

The wider R6-WP6.18 human playthrough hard stop remains active after merge.
