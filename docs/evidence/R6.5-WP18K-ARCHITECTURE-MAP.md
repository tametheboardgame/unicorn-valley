# R6.5-WP18K architecture and removal map

Date: 8 September 2026  
Baseline: `d8f3de6f264fa5fd6e2d77d539a47f288eb50cd4`

## Scope and method

This is the required K1 evidence before deletion. Imports, scene registration,
manager construction, object-name dependencies and browser assertions were
traced from `src/main.ts`, `BootScene`, scene owners and tests. A file is not a
deletion candidate merely because it uses `POST_STEP`; domain managers remain
outside presentation consolidation unless they are demonstrably unreachable.

## Boot and scene registration

`gameConfig` owns eager core scenes. `src/main.ts` installs cross-scene managers
and lazily registers Inventory, Wonderbook, Shop and secondary interiors. The
dynamic registrations are active dependencies and remain until the later
readiness/error contract owns changing them. K may group installation and add
explicit ownership, but must preserve code splitting and entry readiness.

## K2-K4 implemented consolidation

- Deleted the unreachable `DesktopConceptPresentationManager` and
  `CrystalBrookEchoBridgeManager`; neither had an import, dynamic-import string or
  caller.
- Deleted the WP18J responsive polish and map-clip pollers. Their accepted Bag
  geometry, glyph-only close target, Map drag layer, fixed North marker and
  renderer-independent cameras now belong to `InventoryScene` at creation time.
- Deleted `BagInPersonShoppingManager` and the underlying hidden Bag Shop control.
  The accepted no-shortcut behaviour now exists structurally rather than through
  every-frame suppression.
- Removed Inventory from the generic modal rectangle scanner because the scene
  creates its canonical rounded surfaces directly. Other modal owners remain on
  the transitional scanner pending safe scene-by-scene migration; this package
  does not pretend that renaming it is consolidation.
- Updated historical browser assertions for suggestion cards, the Controls
  panel, Bag Shop and generic Inventory wrapper graphics to assert the accepted
  product behaviour instead of resurrecting retired objects.

## Planned versus actual scanner retirement

K1 proposed full retirement of both remaining scanners, but trace-led implementation did **not** complete that claim:

- `DesktopConceptCleanupManager` survives only to suppress four scene-owned atmosphere controls, E/Enter/tap instruction copy, old fixed location copy/shadows and world-level legacy action prompts. Removing those source objects crosses many world/content owners and the approved WP19D interaction redesign, so preserving the accepted no-duplicate presentation is safer than deleting the scanner in K. **WP19D** owns replacing world interaction/instruction creation at source; **WP19F** owns the remaining atmosphere/location presentation cleanup.
- `ModalConceptPresentationManager` no longer scans Inventory. It still rounds named rectangles in Wonderbook, Unicorn Creator, Shop and Cottage Decorate; Settings opts out because it owns its surfaces. Removing this compatibility presentation before those scenes create equivalent surfaces would visibly regress the accepted shell. **WP19C** owns Creator, **WP19F** owns Wonderbook/general UI consistency, and existing Shop/Decorate owners retain their scene migration until that package.
- `UiProductionPresentationManager` survives only for Shop and Cottage Decorate frame/ornament/reduced-motion presentation. It is not an Inventory, Settings, Wonderbook or dialogue owner. **WP19F** is the later consolidation owner; WP19G/H may use its established lifecycle but do not silently inherit visual redesign.

Therefore WP18K retires five proven managers/bridges and both WP18J pollers, but does not claim full cleanup/modal scanner retirement. The retained responsibilities are explicit compatibility boundaries, not hidden completed work.
