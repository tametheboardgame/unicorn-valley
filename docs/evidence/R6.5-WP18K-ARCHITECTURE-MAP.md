# R6.5-WP18K architecture and removal map

Date: 8 September 2026  
Baseline: `d8f3de6f264fa5fd6e2d77d539a47f288eb50cd4`

## Scope and method

This is the required K1 evidence before deletion. Imports, scene registration,
manager construction, object-name dependencies and browser assertions were
traced from `src/main.ts`, `BootScene`, scene owners and tests. A file is not a
deletion candidate merely because it uses `POST_STEP`; domain managers remain
outside presentation consolidation unless they are demonstrably unreachable.

## Canonical ownership

| Concern | Canonical owner | Dependencies and preservation boundary |
| --- | --- | --- |
| Exploration shell lifecycle | `ExplorationShellWorldManager` and `ExplorationShellConfig` | Ensures one `ExplorationShell` per supported world scene and starts the static overlay scene. |
| World-local interaction/navigation | `ExplorationShell` | Owns movement pad, contextual action and `ExplorationChrome`; must preserve Gallop and tap navigation authority. |
| Static HUD | `ExplorationHudOverlayScene` | Owns camera-independent Map/Bag/Book/Settings, Shimmer and location presentation. Its static-camera geometry is accepted. |
| Responsive class selection | `ResponsiveLayout`, `LandscapeTabletPresentation` and the portrait media-query entry points | Four required classes remain desktop/laptop, tablet landscape, phone landscape and phone portrait. |
| Bag and Map contents | `InventoryScene` | Product owner for categories, no Shop shortcut, map geography and modal lifecycle. |
| Map drag and hard clip | currently split between `Wp18jResponsiveUiPolishManager` and `Wp18jMapViewportClipManager` | Transitional WP18J layer. Consolidate into `InventoryScene` while preserving fixed North, drag bounds and renderer-independent camera clipping. |
| Wonderbook contents | `WonderbookScene` | Product owner for page tabs and cross-only close. |
| Generic modal decoration | `ModalConceptPresentationManager` | Transitional scanner/redrawer. Move stable surfaces into modal scene/component creation, then retire the scanner. |
| Legacy exploration suppression | `DesktopConceptCleanupManager` | Transitional scanner that hides old copy/shapes. Replace with source-owner retirement; do not preserve hidden resurrection paths. |
| Production UI fallback | `UiProductionPresentationManager` from `BootScene` | Older production skin. Retain only behaviour not superseded by canonical scene-owned presentation. |
| Creator responsive controls | landscape and portrait creator managers | Preserve behaviour pending the separate WP19C redesign; K may consolidate lifecycle only. |
| Race touch controls | `RaceMobileControlsManager` plus race control authority | Preserve RUN/JUMP and assistance semantics; no racing redesign. |

## Boot and scene registration

`gameConfig` owns eager core scenes. `src/main.ts` installs cross-scene managers
and lazily registers Inventory, Wonderbook, Shop and secondary interiors. The
dynamic registrations are active dependencies and remain until the later
readiness/error contract owns changing them. K may group installation and add
explicit ownership, but must preserve code splitting and entry readiness.

## Removal evidence and planned disposition

| Candidate | Reachability evidence | K disposition |
| --- | --- | --- |
| `DesktopConceptPresentationManager` | No import or caller exists; only its own exports reference the class. The canonical shell comment in `main.ts` explicitly rejects layering it. | Delete as unreachable legacy UI, including tests/assets only if exclusively referenced by it. |
| `DesktopConceptCleanupManager` | Constructed by `main.ts`; scans every active scene and hides old prompts/shapes. | Replace old prompt creation at source, then delete. Its location-label fallback is superseded by the static HUD. |
| `Wp18jResponsiveUiPolishManager` | Constructed by `main.ts`; mutates Inventory objects and repairs pressed navigation scale every 80 ms. | Move stable Bag/Map construction to `InventoryScene`; replace pressed-state repair with lifecycle-safe controls; delete manager. |
| `Wp18jMapViewportClipManager` | Constructed by `main.ts`; waits for polish-manager objects before adding map cameras. | Move camera setup into Inventory Map creation after its objects exist; delete manager. |
| `ModalConceptPresentationManager` | Constructed by `main.ts`; scans named rectangles every 120 ms. | Make modal owners create canonical rounded surfaces, then delete scanner. |
| `ExplorationShell`, `ExplorationChrome`, `ExplorationHudOverlayScene` | Directly created through the active shell manager and interaction prompts; browser tests assert the overlay. | Canonical; retain and clarify boundaries. |
| `CrystalBrookEchoBridgeManager` | Exported getter has no repository caller. | Verify no dynamic string import, then delete as unreachable world bridge without changing NPC authority. |
| `UiProductionPresentationManager` | Dynamically installed by `BootScene`. | Audit object-level overlap; do not delete wholesale until surviving title/dialogue behaviour has a canonical owner. |

## Test disposition

Keep behaviour coverage for static HUD geometry, four display classes, Bag
categories, Map drag/North/clipping, Wonderbook tabs/cross close, modal cycling,
save/continue, movement and racing. Assertions for `activity-suggestion-card`,
`exploration-controls-button`, Bag Shop and generic
`concept-modal-surface:*` wrappers describe retired implementations and should
be rewritten around current child-visible behaviour, not restored.

## Guardrails and gate

No save/schema, progression, economy, NPC authority, movement, race, content,
topology or collision change belongs here. Cottage back-wall/window collision
remains open. Technical validation and the immutable preview must be complete
before David's separate four-class visual-regression spot check; no WP18K merge
or production deployment is authorised.
