# R6.5-WP19F title artwork evidence contract

## Approved direction

David approved proceeding without further design input on 11 September 2026. The working direction is approximately 60% cosy storybook, 30% magical fantasy and 10% adventure.

The title artwork must feel like Unicorn Valley rather than an unrelated high-budget 3D game. It should be warm, inviting and polished, with hand-painted storybook character.

## Composition contract

The canonical scene should include:

- an inviting cottage as a recognisable home anchor;
- a winding path leading into the valley;
- flowers and layered meadow detail;
- magical woodland framing the valley rather than dominating it;
- gentle rainbow or magical light in the distance;
- small or distant unicorn life where useful for identity, while leaving the existing live personalised hero unicorn as the main foreground character;
- a calm upper region for the live `UNICORN VALLEY` title;
- a calm right-side region for the live menu on landscape layouts;
- no baked-in title, logo, labels, buttons, signs with writing or other UI text.

The production artwork must avoid photorealism, glossy faux-3D rendering and visual noise behind interactive controls.

## Responsive contract

Artwork approval applies to the generated scene together with the live controls, not the isolated image.

Evidence covers:

1. desktop, 1280x720;
2. tablet landscape, 1024x768;
3. phone landscape, 844x390;
4. phone portrait, 390x844.

Landscape and portrait are intentional compositions. The portrait presentation preserves the cottage/path/valley identity rather than relying on a blind centre crop that hides the subject.

## Runtime integration contract

- Existing title/logo/menu controls remain live Phaser/DOM controls above the artwork.
- The saved-profile hero unicorn remains live and personalised.
- Continue remains primary when a valid save exists.
- New Game retains overwrite protection.
- Settings and unicorn redesign/recovery routes remain available as appropriate.
- The existing primitive title background remains the readable loading/error fallback.
- Only the derivative appropriate to the current title presentation is preloaded, and only while `TitleScene` is active.
- Artwork loading failure does not block menu interaction.

## Asset contract

Committed production paths:

- canonical production master: `public/assets/title/wp19f-title-master.webp`;
- landscape runtime derivative: `public/assets/title/wp19f-title-landscape.webp`;
- portrait runtime derivative: `public/assets/title/wp19f-title-portrait.webp`;
- provenance and verification: `docs/evidence/R6.5-WP19F-TITLE-ASSETS.json`.

The asset evidence JSON records measured dimensions, byte sizes, SHA-256 checksums, Git blob IDs, generation provenance and the source/derivative relationship. The generated high-resolution source binaries are described by measured metadata in that record; the repository retains the compact canonical production master plus normal runtime derivatives needed by the game.

Binary transfer used one validated whole-file blob per committed asset. The package does not construct images from pasted Base64 fragments.
