# R6.5 WP17 Playtest Remediation Plan

Date: 2026-09-05
Status: planned remediation following failed human readiness gate

## Why this plan exists

R6.5-WP17 produced useful human evidence, but it did **not** release the R7 readiness gate. The playthrough found major landscape-tablet control/readability blockers, multiple hard freezes, several functional defects, and a set of world/visual/content issues that materially affect free play.

The correct response is bounded remediation under R6.5, followed by another full human tablet playthrough. R7 remains blocked until WP17 is explicitly released after that replay.

## Product-direction decision

Unicorn Valley is now to be designed **landscape-tablet-first from an interface and control perspective**.

This does not mean abandoning browser delivery or desktop compatibility. The existing Phaser/TypeScript/Vite codebase remains the product codebase. Desktop keyboard/mouse support remains valid, but it is no longer the design authority for exploration controls, interaction prompts, menus, inventory, racing or child-facing instructions.

The reference human-test device for this remediation phase is:

- Samsung Galaxy Tab S8;
- current Android version available for that device;
- Chrome;
- landscape orientation.

Other modern landscape tablets must remain usable, including common 16:9, 16:10 and 4:3 shapes. Desktop/laptop remains a supported secondary presentation.

### Native Android decision

Do **not** rewrite Unicorn Valley as a native Android game.

The observed problems are primarily presentation, touch-control, interaction, stability and content-quality problems. A native rewrite would discard substantial working game logic, content, save behaviour, tests and browser tooling without directly solving those design defects.

A later Android package of the existing game remains viable. After the tablet-first web build is stable and accepted, a later R6.6 package may evaluate packaging the existing Phaser/Vite application with Capacitor or an equivalent thin Android wrapper. That packaging work is explicitly outside WP18A-H and must not distract from fixing the game itself.

## Priority order

The remediation programme must preserve this order of importance:

1. landscape-tablet UX architecture and human-approved concepts;
2. freezing, resilience and stability;
3. landscape-tablet controls, interaction and shell implementation;
4. actual functional bugs and regressions;
5. bag/map/menus/creator and broader modal UX;
6. world consistency, visual quality and daughter-led content improvements;
7. device hardening and complete replay.

A later package may work on a lower-priority item only when it does not conceal or defer an unresolved higher-priority blocker.

## Canonical playtest evidence

The following observations are the source material for this remediation phase. Human evidence takes precedence over earlier automated assumptions that a surface was already fixed.

### A. Controls, tablet UX and instructions

- The child player said: "It's mostly the controls that are the problem."
- Race controls in landscape obscure the track and upcoming obstacles.
- On the Galaxy Tab S8, holding RUN can trigger Chrome long-press/navigation UI, interrupting the press and making races effectively unusable.
- The same behaviour was not reproduced on the user's phone, so the exact failure is device/browser/input-context sensitive.
- Gallop is positioned so the player cannot comfortably use direction controls and Gallop together. The child noted that it needs two fingers.
- Point-and-click/tap-to-move was the child's preferred movement method because it was easiest.
- Help/instruction text is computer/keyboard-oriented on tablet and caused confusion.
- The controls/settings panel includes concepts such as toggles being on/off that were confusing to the child.
- Some text is too small on tablet.
- The shell contains too many competing boxes, labels and buttons, particularly around the top of the screen.
- Text can overflow boxes and boxes/buttons can overlap.
- The child described there being "a lot of buttons" and being confused by some of the buttons at the top.
- Primary interactions are inconsistent: some characters respond to direct tapping, while others rely on a large Talk button.
- The desired interaction rule is that both sensible direct-tap interaction and the clear contextual action button should work consistently for applicable NPCs.

### B. Freezing and severe stability failures

- Full game freeze in Hollow Tree Nook / Tree Nook during normal play.
- Full game freeze in Twinkle and Thread during normal play.
- Repeatable Sunlit Beach failure: opening the bag causes everything except the sand to disappear and the game freezes.
- These are release-blocking defects. Stability investigation must identify root causes rather than apply unrelated performance tweaks.

### C. Functional defects

- Echo cannot be spoken to. Neither direct tapping nor the contextual interaction route works.
- The Moonflower Cottage interior allows the player to walk up/through the back-wall area because collision boundaries are wrong.
- Cottage decoration state is inconsistent: placed items appear to remain in the bag, and selecting an empty slot does not reliably clear placement.
- The bag only exposes six visible items and has no scrolling or paging, making later items inaccessible.
- Food can be collected and stored but cannot be eaten or otherwise used.
- Bakery purchasing feedback is unclear. The player could not reliably tell a purchase succeeded and consequently bought repeated croissants.
- Some earnings/reward feedback is unclear to the player.
- Maple could not be found despite the player actively searching for her to continue missions/unlocks. Root cause is not assumed in advance.
- Point-and-click backward movement has previously caused rapid facing-direction flicker and must be revalidated against the real tablet flow.
- Any remaining circle/placeholder/icon representations over or instead of unicorn bodies must be treated as regressions even if older automated reconciliation considered them resolved.

### D. NPC/world-state consistency

- A core NPC can currently appear in multiple places or activities simultaneously.
- Nova is the strongest example: she can remain at the race location while also participating in the picnic and visiting the cottage.
- Some of these appearances use symbols such as a star or race flag instead of Nova's unicorn form.
- The player noticed that a symbol representation can appear while the character's body remains elsewhere.
- The long-term design direction is a core recurring cast with authoritative presence/activity state: one character cannot occupy mutually exclusive locations or activities at the same time.

### E. Inventory, map and shell redesign direction

- Bag and map should move away from large permanent shell panels toward clear compact controls/icons near the primary UI.
- Map should have its own explicit control rather than being conflated with other shell UI.
- Inventory should be redesigned around clear categories/pockets, inspired by the useful organisational principle of games with separate item pockets.
- Candidate categories include Food, Quest Items and other categories justified by actual content.
- Lists inside a pocket must scroll and remain readable/tappable on tablet.
- Food should become meaningfully usable. A candidate future mechanic is temporary food effects, for example a croissant granting a short movement-speed boost. Exact effects require bounded design rather than automatic implementation from the example.

### F. Quest/readability/discoverability observations

- The child understood much of the game but sometimes could not work out what to do because instructions were unclear or device-inappropriate.
- The child spent most of the session looking for people, completing missions and trying to unlock more things.
- Directions such as Pebble's "a grassy field on the far side of the story house" were not sufficiently clear to the child.
- The child could generally remember how to return to the cottage, but sometimes mixed up Unicorn Town and the following area.
- The child actively wanted to continue questing and searching rather than being passively led through a linear sequence.

### G. Visual and world-quality observations

- Rainbow Meadow received positive visual feedback and should not be redesigned merely for change.
- Whispering Woods was liked, while the child also wanted it to feel even more magical.
- Tree Nook was described as "really cool" and the mushrooms were specifically loved.
- The child wanted the mushrooms to do something, suggesting that attractive environmental objects can support lightweight interactions.
- Shell Cove does not convincingly read as a cove.
- Crystal-area triangular forms do not clearly read as crystals/stalactites; the child suggested more recognisable gem/crystal silhouettes.
- Sunbeam Village shops still need a stronger place/identity/interior pass.
- The Crystal Brook approach/gateway still warrants a more convincing path/cave-like entrance treatment.
- Unicorn neck/mane proportions look wrong to the child and user. More mane coverage helps; the child described the neck as "a bit too saggy".
- Pip and some other unicorn presentations can read as circles/balls or symbol placeholders rather than full unicorn characters.

### H. Daughter-led content ideas to preserve

These are not mandatory bug fixes, but should be retained for the later improvement package and R7 evidence:

- unicorn sandcastles at the beach;
- interactive mushrooms;
- usable/eatable food;
- temporary food abilities/effects as a possible mechanic;
- a Unicorn Palace unlocked after many good deeds/quests, with a king or queen inviting the player and providing further problems/quests;
- multi-step social events such as helping prepare/fix things for a party;
- richer recurring friend characters whose activities and presence are coherent.

### I. Strong positive signals

The remediation must preserve what already works:

- Rainbow Meadow appearance was liked;
- Whispering Woods was liked;
- Tree Nook and its mushrooms were strongly liked;
- Firefly activity was loved;
- the child appreciated that collected fireflies map clearly to Star Coins;
- earning currency, discovering things and spending money were enjoyable;
- questing/unlocking motivated most of the child's self-directed play;
- point-and-click/tap movement was independently chosen as easiest;
- when asked whether she would play again, the child said yes.

## WP18 remediation sequence

### R6.5-WP18A - Landscape Tablet UX Concept and Approval

Human-gated concept package. Produce and iterate visual concept images before shell/control implementation. Required concept surfaces:

1. normal landscape exploration shell;
2. landscape race controls;
3. bag/inventory plus map-access direction;
4. unicorn creator direction.

Concepts must show realistic game-world space and control placement, not abstract wireframes only. The user approves the visual/control direction before WP18C implements it.

### R6.5-WP18B - Freeze Diagnostics, Root Cause and Stability

Instrument scene/input/runtime lifecycle sufficiently to diagnose all observed freezes. Reproduce and fix the known Tree Nook, Twinkle and Thread and repeatable Sunlit Beach bag failures. Add stress/regression coverage for repeated transitions, modal open/close, shops, races and long continuous sessions.

### R6.5-WP18C - Landscape Tablet Controls and Interaction Shell

Implement the approved tablet-first shell as a shared system. Preserve keyboard/mouse as secondary input. Standardise contextual action presentation, direct NPC tapping where appropriate, touch handling, multi-touch safety, gallop/run behaviour and device-appropriate help.

### R6.5-WP18D - Playthrough Functional Bug and Regression Remediation

Resolve the remaining functional defects captured by the playthrough, including Echo interaction, cottage collision/decor state, Maple discoverability/root cause, purchase/reward feedback, facing flicker and any remaining placeholder/icon-over-character regressions. Every confirmed defect receives a regression that represents the human failure mode where practical.

### R6.5-WP18E - Bag, Map, Creator and Modal Tablet UX

Apply the tablet-first design language beyond the exploration shell. Redesign inventory around scalable scrolling/category behaviour, provide explicit map access, refine creator into progressive categories rather than a cramped all-at-once control surface, and reconcile shops/Wonderbook/settings/dialogue/activity modals with the same readability and touch-target rules.

### R6.5-WP18F - World Consistency, Visual Quality and Experience Improvements

Address core-cast authoritative presence/activity state, character-symbol inconsistencies, unicorn neck/mane presentation, Shell Cove identity, Crystal Brook/crystal readability, shop-place quality and selected daughter-led environmental interaction improvements. Preserve strong existing visual areas rather than performing indiscriminate redesign.

### R6.5-WP18G - Tablet Device Hardening and Cross-Input Regression

Validate landscape touch presentation across common tablet aspect ratios and coarse-pointer environments, with the Galaxy Tab S8 as the human reference. Block browser gesture interference, validate safe areas and orientation behaviour, preserve desktop keyboard/mouse support, and keep the 520 KiB application-entry performance budget unchanged.

### R6.5-WP18H - Full Human Tablet Replay and Return to WP17

Run another substantially unguided human playthrough on the reference tablet. Confirm controls, readability, stability, interaction consistency, progression, racing and general world quality through real play. WP18H does not release R7 itself: it returns the project to WP17 for the user's explicit readiness decision.

## Dependency chain

`WP17 evidence -> WP18A -> WP18B -> WP18C -> WP18D -> WP18E -> WP18F -> WP18G -> WP18H -> WP17 readiness decision -> R7`

WP18B is technically independent of the visual concept content, but remains sequenced after WP18A so the project has one clear operating order. No shell implementation may begin before WP18A human approval.

## Cross-package design rules

1. Landscape tablet is the primary interface authority.
2. Point-and-click/tap movement is a first-class control scheme, not merely an accessibility fallback.
3. Direction controls remain available for players who prefer them.
4. Primary actions must look unmistakably actionable.
5. Child-facing instructions describe the controls actually present on the current device.
6. The world should occupy most of the screen. Permanent chrome must justify its space.
7. Avoid multiple competing boxes/labels when hierarchy or progressive disclosure can communicate the same information.
8. Text must wrap or scroll intentionally. Silent clipping and overlap are defects.
9. Inventory and other growing collections must scale beyond their initial item count.
10. Core recurring NPCs need authoritative presence/activity state if they participate in multiple systems.
11. Human-observed defects override stale automated claims that a surface is already fixed.
12. Positive human evidence is a preservation requirement, not merely commentary.

## Technical invariants

- Keep the existing Phaser/TypeScript/Vite codebase.
- Preserve save compatibility unless a bounded migration is necessary and explicitly tested.
- Keep the hard application-entry performance budget at **520 KiB**.
- Do not weaken automated CI/browser coverage to make remediation pass.
- Production deployment still requires explicit user approval.
- No R7 implementation begins while WP17 remains unreleased.

## Final acceptance for WP18

WP18 is complete only when:

- no known hard freeze remains reproducible;
- landscape tablet controls no longer block ordinary exploration or racing;
- no major tablet readability/overlap issue remains;
- primary interactions are obvious and consistent;
- the bag/map/creator/modal surfaces scale and remain usable by touch;
- playthrough functional regressions are resolved and covered;
- core world/character consistency defects identified above are resolved or explicitly bounded with user approval;
- a full human replay has been completed on the reference tablet;
- the project has returned to WP17 for a new explicit R7-readiness decision.
